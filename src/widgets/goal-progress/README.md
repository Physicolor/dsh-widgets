# goal-progress — 目标进度

## §0 审计（动手前逐条回答，BRIEF V3 §0）

**1. 这个信息是不是已经在别处更方便地展示了？**
没有。`goal` 投影在 DSH 的 Web UI 里**没有任何消费者**：输入框下方状态条只有会话量（turns/steps/上下文），页头不显示目标，设置页只有权限 / 模型 / preset；「这个自主目标跑到第几轮、是不是被卡住了」目前只能翻对话或读 transcript。唯一可能"别处更方便"的候选是目标创建时用户在对话里写下的 objective —— 但那是**当时的意图**，不是**现在的状态**（阶段、轮次、阻塞原因），两者不是同一件事。结论：做。

**2. 有没有功能高度重合的既有组件？**
逐一比过下面四张，**窗口 / 范围 / 单位 / 时态**四栏都不同：

| 既有组件 | 它的窗口/范围/单位/时态 | 与本卡的差异 |
| --- | --- | --- |
| `task`（任务，order 22） | `todos` 待办清单：条目 + 状态（进行中/待办/已完成），**无时间点、无预算** | todos 是**用户看得见的工作清单**，会随聊天增删；goal 是驱动会话**自行续跑**的持久承诺。一个会话可以没有 goal 却有 todos，反之亦然 |
| `counts`（轮次·步数） | `turns` / `steps`：**一段会话的对话量**，单调上涨，**无上限** | 那是"聊了多少"；`roundsStarted / maxGoalRounds` 是"自主目标用了多少轮预算"，**有预算表**，只在与 goal 有关时有意义。名字里的"轮次"不是同一个东西，所以本卡把它标成「轮次/上限」并带上限 |
| `context-water` / `context` | 上下文窗口占用：**token 占比**，越高越坏 | 单位是 token、语言是"水位"，与目标生命周期无关 |
| `compactions`（上下文压缩） | 压缩次数 / 回收量：上下文折叠的账 | 与目标无关；goal 被阻塞时也不会压缩 |

没有可以合并的对象：删掉本卡，`goal` 投影就再次变成**零消费者**。

**3. 如果不合并，用户不读文档怎么分清这两张？**
名字：`目标进度`（不是「轮次」）。大数字：**阶段词**（进行中/已暂停/受阻/已完成/无目标）——一个不可能是 `轮次·步数` 那张卡的数字的词。灰字第一句：受阻时是 `原因：…`，无目标时是 `当前会话没有目标`。三处都自报身份。

**4. 这个大数字是什么单位、什么范围、什么时间点？**
**它是一个词，不是一个量**：`GoalInfo.phase` 的五种取值（`active` / `paused` / `blocked` / `complete`）+ 空态的 `无目标`。范围就是这五个字符串，时间点是"此刻"（投影的最新快照）。这正是本次修订的核心：以前这里印的是 `roundsStarted / maxGoalRounds`，**那两个数需要一句话解释才看得懂**（`0 / 256` 尤其），不合格；现在换成不需要解释的词。

> `0 / 256` 的来历（写进这里，不再猜）：DSH 自己的 `dsh-goal` 配置项 **`defaultMaxGoalRounds` 默认就是 256**（源码 `static Config = z.object({ defaultMaxGoalRounds: z.number().default(256) })`）。所以任何用 `create_goal` 建、还没准入过任何轮次的 goal 都是 `roundsStarted = 0, maxGoalRounds = 256`；`0 / 12` 同理（那次显式传了 `maxGoalRounds: 12`）。**一个还没有任何轮次的 goal，印出它的上限不是进度，是噪音。**

**5. 它应该一直在，还是可以消失？**
**一直在。** 它是用户主动装进 rail 的卡（`defaultInstalled: false`），缺数据时"突然出现/消失"会打乱布局；现在 `goal === null` 走**安静空态**（标题 + 阶段词「无目标」+ 一行说明，两行压在卡片左下角贴底），不再 `return null`（V3 §1.4 的第一条）。

**6. 颜色有没有被赋予一个用户能说出的含义？**
有，且只有一处：**受阻 → 红**（大数字染 `valueTone: 'danger'`），含义是"跑不动了、在等你动手"，是唯一的危险等级。**已完成不再是绿色**：绿/黄/红是升级阶梯（V3 §0.6），"完成"不是警示等级；而且渲染器的 `valueTone` 只有 `danger` / `warn` / `muted` 三档，传 `success` 会掉进 `valueColor` 的兜底分支变成**红色**（这是个陷阱，所以旧版「阶段」行的绿是删除而不是搬走）。进度本身一律不染色。

## 1. 这张卡回答什么问题

**这个会话的自主目标现在处于什么阶段（有没有被卡住、卡在哪），以及它到底跑了多少轮。**
当会话挂了 goal 时会自动一轮轮跑下去，而阶段、被什么卡住、轮次上限这三件事在 rail 上完全不可见——只能翻对话猜。

## 3. 数据来源

只读 `WidgetStats.goal`（`GoalInfo`，采集器已归一化，同步投影，**无异步源**，所以 manifest 不写 `source`/`skeleton`）：

| 字段 | 用途 | 口径 |
| --- | --- | --- |
| `phase` | **大数字**（阶段词）、是否染红 | `active` / `paused` / `blocked` / `complete` 四值；空态另用第五个词「无目标」 |
| `objective` | 明细第 1 行「目标」的值 | 按当次渲染算出的列预算截断；空串 → `—` muted |
| `roundsStarted` | 明细第 2 行「轮次/上限」 | 已准入的轮次。**`0` 时改印「尚未开始」**，不印 `0 / N`；`complete` + `0` 时印 `—` muted |
| `maxGoalRounds` | 同上的分母 | `<= 0`（没发布上限）→ 分母印 `—`（`12 / —`），不印 `12 / 0` |
| `updatedAt` | 明细第 3 行「最近变更」 | epoch ms；`<= 0` → `—` muted；≥30 天 → 印日期（`fmtShortDate`），不套「前/ago」 |
| `blockedReason.message` | 受阻时的灰字 | 截断；缺失时灰字整行不出现（不留空行） |
| `createdAt` | **不读** | 本卡只关心「最近一次动」；创建时间对阶段与预算消耗没有解释力 |

`null` / `[]` / `—` 各是什么：

- `stats.goal === null`（本会话没有目标）→ **安静空态**：「无目标」+ 一行说明压在卡片左下角贴底，**不返回 null**（本次修订的第一条要求）。
- `—` 只用于「有这一行、但这个读数拿不到」：空 objective、`complete` + 0 轮、`updatedAt <= 0`。三处都配 `tone: 'muted'`（占位不等于坏消息，绝不染红）。`尚未开始` **不是**占位，所以**不** muted。
- 本卡没有 `[]` 这种形态（一个会话只有一个 goal，没有列表）。

**沿用共享格式化器**：`fmtAgo`（12s / 5m / 3h / 6d，≥30 天转 `fmtShortDate`）与 `fmtShortDate`。不用 `fmtDuration`：它只服务分钟级时长，一个两天前动过的 goal 会被印成 `2880m0s 前`。

## 4. 元素为什么这么摆

- **大数字在标题正下方（`headAfter.big`，不是 `value`）**：BRIEF §2 的头部阶梯（蓝标题 → 20px 大数字 → 灰字），也是 `任务` / `缓存命中` 的同一套节奏。**有目标时** `value` 留空，否则同一条读数会被渲染器再推进正文印第二遍。**空态是唯一的例外**（见下一条）：那时版式里根本没有明细行，`value` 才成为正文大字的正确落点。
- **空态的两行放在左下角、贴底（`value` + `sub` + `bodyAnchor: 'bottom'`，第二版修订）**：这是本轮唯一的改动。旧版空态沿用头部阶梯（`headAfter.big` = `无目标` + `legend` = `当前会话没有目标`），两行被钉在标题正下方——实测 `无目标` 距卡片下沿 **92px**、灰字距下沿 **76px**，而下面 76px 全是空的，一张「安静的空卡」看起来像一张「没画完的卡」。空态没有明细行去压住卡底，所以这两行**就是**它的正文：`value`（20px，正文大字位）+ `sub`（10px 灰字）+ `bodyAnchor: 'bottom'`（正文贴底，`额度管理` 的数字行是同一姿态）。实测（离线画廊真 DOM，150×150 卡片）：`无目标` 左 13px / 下 33px，`当前会话没有目标` 左 13px / 下 13px（卡片 pad 12 + 1px 边框 → 字盒底边正好落在内容区下沿），富余的 67px 全部落在**标题与这两行之间**。
  - 为什么**不**用 `headAfter` + `bodyAnchor: 'bottom'`：`bodyAnchor` 锚的是**正文**，而那个组合下正文是空的，被锚住的什么都没有，头部两级仍堆在顶上——正是要被修掉的那个形态。契约里 `headAfter` 与 `value` 互斥（有 `headAfter` 时 `value` 会被推进正文）这件事，反倒让这个分支成为可能：空态不给 `headAfter`，`value` 就干净地成为正文大字。
  - **有目标时的版式一个字没动**：改动只在 `g === null` 的那个分支里。用改动前后的真 DOM 几何逐格比对过五个态，**state 2–5（进行中 / 刚创建 / 受阻 / 已完成）逐字段完全相同**（title / headAfter / legend / value / sub / rows / 卡片盒 / scrollHeight 全等），差异只出现在 state 1（空态）。
- **大数字是阶段词而不是数字对**：见 §0 第 4 问。五个词穷尽了这张卡能回答的状态；空态也用同一个词表（`无目标`），所以卡上**永远只有一个"当前状态"的词**，它只是换了个落点（有目标在标题下，没目标在左下角）。
- **「轮次/上限」是一行，不是大数字**：`12 / 40` 只有在**至少准入过一轮**之后才是进度；在那之前没有进度可言，只有上限——`0 / 256` 就是这么来的。标签把两半都说清（轮次 / 上限），因为一对裸数字只有配上"已用 / 允许"才有意义（`任务` 的计数行是同一纪律）。没发布上限时印 `12 / —`：十二轮，但没有可比的分母。
- **`0` 轮时印「尚未开始」而不是 `—`**：`—` 在本仓库是"这个读数拿不到"的语言，而这里恰好相反——读数拿得到，它就是"还没开始"。唯一例外是 `complete` + `0` 轮：那时「尚未开始」会和上面的「已完成」自相矛盾，所以印 `—` muted。
- **灰字（legend）只在一处出现**：受阻时载**原因**（跑不动时"为什么"比别的一切都重要，而这句话在卡上别处没有位置）。其余状态**整行不出现**——其它读数各自占了明细行，本仓库的规矩是一条读数只印一次，灰字不能变成第二块牌子。这也让「受阻」明显不同：多出的一行就是"需要你动手"。**空态不用 `legend`**：它那行说明走 `sub`（正文灰字，贴底），因为空态的要点正是"把仅有的两行压到卡底"，而 `legend` 是头部的一级，位置由标题决定、不受 `bodyAnchor` 影响。
- **三行明细贴底（`bodyAnchor: 'bottom'`）**：与既有一切带 `headAfter` 的卡同一姿态——富余高度落在灰字与分隔线之间，而不是压在行下面。**有灰字 134/150，没灰字 120/150**，都在 150 的格子里（实测 `clientHeight 148 / scrollHeight 148`，无 `data-dsx-overflow`）。空态同一姿态但更矮：pad 24 + 标题 16 + 正文 43 = **83/150**，余下的 67px 就是上面草图中标题与两行之间那块空。
- **目标行的截断预算是算出来的，不是写死的**：`breakdown` 的标签轨（`1fr`）与数值轨（`auto`）被三行**共享**，所以最宽的标签决定了最宽的值能有多少地方——`轮次/上限` 在 zh 是 45.6px、`Rounds/max` 在 en 是 56px，一个常量必然在一门语言里溢出。`objectiveBudget()` 用实测的列模型（124px 行宽 / 8px 间隙 / ASCII 5.6px / CJK 10px / `…` 占 2 列）当场把预算算出来。zh 得 10 列、en 得 8 列，实测每行 `标签 + 8px + 值 ≤ 124px`。
- **≥30 天的「最近变更」印日期**：`fmtAgo` 过 30 天会转成 `fmtShortDate`（`8.14`）。旧版无条件套「前 / ago」，于是一个月前动过的 goal 会印 **`8.14 前`**——一个穿着时长外衣的日期。过界后直接印日期，标签已经说明这是什么。
- **没有 headRing**：环是"占比"的语言。阶段词与轮次上限都不是完成率（目标可能正好需要那 40 轮，提前结束不是成绩），所以没有环。
- **不占 `cycle`、没有 `corner`、没有 `configSchema`**：一个会话只有一个 goal，没有可切换的池视图；本轮也没有需要用户选的选项。

## 5. 语气方向

`tone` 的语义**由本部件决定**，渲染器从不猜：

| phase | 表现 | 依据 |
| --- | --- | --- |
| `active` | 不染（默认 ink） | 正在跑不是结论，更不是坏消息；染绿会让人以为"已完成" |
| `paused` | 不染 | 用户自己停的，不是异常 |
| `blocked` | **`valueTone: 'danger'` → 大数字变红** | 跑不动了且在等外部条件，是唯一需要用户动手的状态（V3 §0.6：红=危险等级） |
| `complete` | 不染 | 完成不是警示等级；且 `valueTone` 没有 `success` 档，传了会被 `valueColor` 兜底成红色 |
| 无目标 | 不染 | 空态不是故障 |
| `—` 占位 | `tone: 'muted'` | 占位不是坏消息 |

**进度本身（轮次行、目标行）一律不染色**：轮次高只说明预算大、用得多，不等于坏（本卡没有任何阈值）。

## 6. 配置项

**无**。本卡没有 `configSchema`，也没有实例级文案键。

## 7. 空态 / 降级行为

| 情况 | 行为 |
| --- | --- |
| `stats.goal` 为 `null` / `undefined` | **安静空态**：标题 + 「无目标」（20px 正文大字）+「当前会话没有目标」（10px 灰字），两行落在卡片**左下角贴底**；无明细行、无分隔线、无颜色。**不返回 null**，卡不会消失 |
| `objective` 是空串或全空白 | 第 1 行值印 `—` + `tone: 'muted'` |
| `roundsStarted === 0` | 印「尚未开始」（不印 `0 / 256`） |
| `roundsStarted === 0` 且 `phase === 'complete'` | 印 `—` muted（「尚未开始」会与「已完成」矛盾） |
| `maxGoalRounds <= 0` | 分母印 `—`：`12 / —`（不印 `12 / 0`） |
| `roundsStarted` / `maxGoalRounds` 非有限数（脏数据） | 一律归 0，绝不印 `NaN` |
| `updatedAt <= 0` | 印 `—` muted，**不编造**距离 |
| `updatedAt` 早于 30 天 | 印日期（`8.14`），不套「前 / ago」 |
| `phase === 'blocked'` 但没有 `blockedReason` | 灰字整行不出现（不印空原因），大数字仍染红 |
| `phase` 是契约外的值 | 理论不可达（`normalizeGoal` 会把非法 phase 整条丢掉，卡此时走空态） |

**这些分支怎么测的**：预览永远带着 `example.stats`（且五个 sim 态由 `meta.sim` 钉住），所以用两个**临时**离线脚本直接验证真实实现：

1. **渲染输出断言**（`.tmp-check/check-empty-state.cjs`，把单元 + i18n 编成 CJS 后 `require`）——**61 条断言全 PASS**：空态三入口（`{}` / `goal: null` / `goal: undefined`）与 `sim: 'none'` 压过实时 goal 时，卡片**恰好只有 4 个键**（`title` / `value` / `sub` / `bodyAnchor`，即没有 `headAfter` / `legend` / `chart` / `valueTone`）；中英双语的空态文案（Node 里没有 localStorage，脚本自己塞一个 `dsh-language` 垫片来切语言）；四个有目标态与**冻结快照**（`render-before.json`）逐字段 diff（只把「42s 前」这类时钟读数归一化，否则快照一分钟就过期）；以及旧轮次建立的读数（`尚未开始`、`12 / 40`、受阻染红 + 原因、完成态 `—` muted、任何状态都不出现 `256`）。
   ```sh
   cd .tmp-check && npx tsc -p tsconfig.json && cd .. && node .tmp-check/check-empty-state.cjs   # 61 passed, 0 failed
   ```
2. **真浏览器几何断言**（`.tmp-check/probe-geom.cjs`）——离线画廊里量五个态的 DOM：空态两行的 `leftFromCard` / `bottomFromCard`（见 §4）、`data-dsx-overflow` 为 null、`scrollHeight === clientHeight`；再与**改动前**跑同一脚本得到的 `geom-before.json` 逐格 diff，证明有目标的四个态一个字段都没动。
   ```sh
   node .tmp-check/probe-geom.cjs .tmp-check/geom-after.json
   node .tmp-check/diff-geom.cjs .tmp-check/geom-before.json .tmp-check/geom-after.json
   ```

三个脚本都在沙箱的 `.tmp-check/`（`.gitignore` 已忽略，不属于交付物）。

## 8. 与既有卡的差异（为什么它不重复）

- `goal` 投影此前**没有任何消费者**：建本目录之前 `src/widgets/**` 下 grep `goal` / `Goal` 零命中。
- 与 `轮次·步数` / `会话概览` 的 `turns` / `steps` **不是一回事**：那两个数是一段会话的对话量，会随聊天一起涨；`roundsStarted` 是 **goal 自己的轮次预算消耗**，`maxGoalRounds` 是那张预算表，两个数只在有 goal 时有意义——所以本卡的标签写「轮次/上限」而不是「轮次」。
- 与 `任务` 不重复：`todos` 是待办清单（条目、状态），goal 是驱动自行续跑的持久目标（阶段、轮次上限、阻塞原因）。
- 与 `上下文压缩` 的「次数/回收」不重复：那是上下文折叠的账，与目标生命周期无关。
- 与 `目标` 类**未来的**卡（如"目标清单"）不重复：`goal` 是**单数**（一个会话一个目标），本卡不是列表。
