# sys-disk — 磁盘与自检（2×4）

> 目录：`src/widgets/sys-disk/`　尺寸：`2x4`（312×150 外框）　数据源：`sys`（`/api/sysinfo` 的 `machine` 切片）

---

## 1. 这张卡回答什么问题

**"这台机器还有地方可写吗，以及 harness 自己在吃掉多少？"**

长跑的失败往往不是模型出错，而是两种运维事故：**盘满**（系统盘低于约 10% 时 Windows 明显降速并开始拒绝更新）与**会话日志膨胀**。既有的 44 张卡全部在回答"用了多少 token / 花了多少钱"，没有一张回答"跑它的这台机器还活着吗"。这张卡把 host 侧新增的 `machine` 自检切片摊开：每个盘的剩余、DSH 会话目录的体积与增速、web 进程自身的占用。

---

## 2. 卡面草图

```
┌─ 312×150 ────────────────────────────────────────────────────────┐
│ 磁盘与自检                                     ← 蓝色标题 13px    │
│ D: 62.9G      剩余 · C: 22% · D: 9%           ← 大数字 20px（紧张盘）｜
│               会话日志 346 文件 · 345M · +13/h  ← 灰字 10px（同排两行）│
│ ······························································  │
│ ··············（25/50/75% 参考虚线，由 bars 渲染器画）·········  │
│                                                                  │
│      ████████（C 22% 剩余）        ███（D 9% 剩余，红）           │
│      C: 67.1G / 300G              D: 62.9G / 652G   ← 9px 灰标签  │
└──────────────────────────────────────────────────────────────────┘
```

- 大数字 = **剩余最少的那个盘的可用量**（"最紧张"才值得当大字；占用量与占用率都不是"会先耗尽"的那个量）。
- 第一行灰字 = 各盘**剩余占比**；第二行灰字 = 会话日志（`home` 读不到时换成 web 进程）。
- 柱 = 每盘一条，柱高 = **剩余 / 总量**，颜色 = 剩余档位。
- 悬停整卡（`cardHint`）＝ web 进程的 PID / RSS / CPU / 运行时长。

## 3. 数据来源

只读 `stats.sysinfo.machine`（`MachineInfo`；host 侧 `src/host/machine.ts`，磁盘 30s、会话目录 60s 各自 TTL）：

| 字段 | 口径 | 卡面上的位置 |
| --- | --- | --- |
| `disks[].mount` / `total` / `free` | `fs.statfs` 的字节数，只含真实存在的固定盘，按盘符序 | 柱（一条一盘）＋柱标签 |
| `home.sessionsFiles` | `$DSH_HOME/sessions` 递归文件数 | 第二行灰字 |
| `home.sessionsBytes` | 上述文件大小之和（字节） | 第二行灰字 |
| `home.recentFiles` | 其中 mtime 在**最近 1 小时**内的文件数（增速信号） | 第二行灰字 `+N/h` |
| `proc.pid` / `rss` / `cpuPercent` / `uptimeSec` | `dsh web` 进程自身（RSS 字节；CPU 为两次采样间的增量，**首个样本为 null**） | `cardHint`；`home === null` 时占第二行 |

**推导全在本目录内**（`index.ts`），没有往共享 `lib/` 加任何东西。

### 3.1 为什么自己写 `fmtBytes`（没有复用 `fmtTokens`）

`src/client/lib/format.ts` 的 `fmtTokens` **顶上只有 M**：652 GB 会被打成 `667648M`；它的"3 位有效数字"规则也是为 token 计数挑的，容量单位要到 G/T 才有意义。所以本地 `fmtBytes` 用 K/M/G/T（1024 进制，与 sys 家族的 `fmtGb` 同一约定），规则是 **<100 保留一位小数、≥100 取整**（`63.0G` / `300G`）。

`fmtUptime` 同理不复用 `fmtDuration`：那是会话时长格式（`45.2s` / `2m42s`），会把 3h54m 打成 `234m0s`。

### 3.2 单位是 1024 进制，标签写 G

`fs.statfs` 报的是原始字节；÷1024³ 得到的其实是 GiB，但仓库既有的 `fmtGb`（sys-cpu / sys-gpu-line 在用）就是这么标注的，**同一栏里的两张卡不能对"G"有两种解释**，所以跟随现状。阅读时按 1024 进制理解即可（本机 C: 322.1e9 字节 → 显示 `300G`）。

### 3.3 `ratio` 是"剩余"，不是"占用"

`ratio = free / total`（规格书的硬要求）。柱高、柱标签、语气三者同向：**柱越短 = 越危险**。若要改成"占用"口径，只需把 `ratio` 换成 `1 - free/total` —— 但那样柱高会与卡面文字里的"剩余 X%"互相矛盾，所以不做（见 §8 遗留）。

## 4. 元素为什么这么摆

**这张卡是"量出来的"，不是排出来的。** 2×4 = 312×150 外框、310×148 客户区、内间距 12 → 内容区 **286×124**。实测（gallery 真浏览器）：

| 块 | 高度 | 说明 |
| --- | --- | --- |
| 标题行 | 16 | 13px × 1.2 |
| `headAfter` 行 | 4 + 25 | 4px 标准间距 + 20px 大数字行框 |
| `bars` 块 | **72** | 56 柱高 + 4 间隙 + 9px 标签行（渲染器写死的几何） |
| 合计 | **117 / 124** | 卡片实测 `client = 148`，`scroll = 148`，**无溢出** |

也就是说：**标题 + 大数字 + 柱状图已经花掉 117px，只剩 7px**。

1. **大数字用 `headAfter.big`**（不用 `value`）：标题正下方一行，是仓库既定的头部阶梯。写成 `D: 62.9G` —— 带上盘符，否则读者要回头在灰字里找"这个红数字是哪块盘"。
2. **灰字两行放进 `headAfter.smallLines`，而不是 `legend` / `sub`**：
   - `legend` 会在头部之下**再加一整行 16px**（16+25+16+72 = 129 > 124，卡片会被撑高、在 rail 上顶破网格行）；`sub` 在柱状图之下**再加一行 18px**（更糟）。
   - `smallLines` 的灰字块是**居中压在大数字自己的行框上**的，两行 12.5px 正好塞进那 25px，**零额外高度**。这就是它存在的理由。
   - 代价：会话日志没能放成真正的 `sub` 行（规格书推荐版式里的写法），但内容一字不少。
3. **第一行 = 各盘剩余占比**（规格书里的 `legend` 内容）：柱只能给出形状，占比必须是个数字；放在大数字旁边，读作"上面这个数属于哪一组"。
   - 超过 3 个盘时只列前 3 个并追加 `+N`：这一行是 20px 大数字**旁边**的 nowrap flex 子项，行内空间不足时 flex 会**按比例同时压缩两个子项**——不封顶的话，读者看到的不是"灰字被截断"，而是**大数字开始出现省略号**（实测 86px 的 `D: 62.9G` 会被压到 84px）。柱状图永远画**全部**盘，所以 `+N` 是诚实的补充而不是隐藏。
4. **第二行 = 会话日志**（`会话日志 346 文件 · 345M · +13/h`）：`+N/h` 的窗口由 host 定义（`recentFiles` = mtime 在最近 1 小时内），所以字符串里不再重复"近 1 小时"，把宽度留给数字本体（会话数会一直涨）。
5. **柱标签带字节对** `C: 67.1G / 300G`：`bars` 渲染器**没有数值列**，一个 datum 只有两个文字出口——柱下的 label 和悬停 title。字节对只能放 label（这也是规格书草图里"柱子右边跟 67.0G / 300G"的唯一可得位置）。盘数超过 3 时退化为 `C: 22%`：标签实测 67–68px，而 4 个盘的列宽只有 68.5px（临界），6 个盘 44px——不退化的标签会互相压过去（该 label 没有 overflow 裁剪）。
6. **`value` = 剩余百分比**，不是字节：该渲染器的悬停 title 写死为 `` `${label} ${Math.round(value)}%` ``，塞字节进去会打出 `67%`（67 GB）。于是悬停读作 `C: 67.1G / 300G 22%`。
7. **web 进程放 `cardHint`（悬停）**：它是规格书草图的第三段，但 150px 里没有它的行位；契约里的 `cardHint` 正是为"不该印在卡面上的诊断信息"准备的。`home` 读不到时它升到第二行（见 §7）。
8. **贴底与否**：`headAfter` 存在时 body 默认顶对齐（`bodyAnchor` 不设），柱块紧跟头部，余量留在卡片下缘——实测 7px，视觉上不空。

## 5. 语气方向

**由本部件定义，绝不让渲染器猜**：这张卡说的是**剩余**空间，所以**越少越危险**——与 利用率（sys-cpu / sys-gpu / sys-rings）**极性相反**（那些卡里 90% 是"忙得发烫"，这里 9% 是"快没地方写了"）。

| 常量 | 值 | 依据 |
| --- | --- | --- |
| `FREE_DANGER` | `0.10` | Windows 在系统盘剩余低于约 10% 时明显降速，并开始拒绝更新 / 服务包 / 卷影副本——不是审美阈值 |
| `FREE_WARN` | `0.20` | 还来得及"计划清理"而不是"抢救"的那一档 |

- 柱的颜色 = 档位（`bars[].tone`：danger / warn / primary）。
- 大数字 = 同一个档位（`valueTone: 'danger'`，契约只允许 danger）：**一个阈值，两处呈现**，卡面不可能自相矛盾。
- **印出来的百分比一律向下取整**（`shownPct`）：档位是严格 `< 10%`，而本机 D: 实测 **9.6%** 剩余——四舍五入会打出"红色 + 剩 10%"，正好停在它本该低于的那条线上。向下取整还保证**永不夸大剩余空间**，是告警该有的方向；柱高与档位仍用精确 `ratio`。

## 6. 配置项

**无。** 本卡第一版不加任何 `configSchema`：刷新节律由壳统一管（已装 `source: "sys"` 的卡取**最短**间隔，缺省 10s；host 侧磁盘 30s / 会话目录 60s 各自 TTL），卡面上没有需要用户选的口径。不加"为了有配置而存在"的配置项。

## 7. 空态 / 降级行为

| 情况 | 行为 | 理由 |
| --- | --- | --- |
| `sysinfo` 缺失 / 非对象 / 老 host 没有 `machine` | `render` → **`null`** | 契约里 `skeleton` 的注释写明：**加载骨架是壳的职责**——widget 分不清"还在飞"与"答了但为空"。本卡**不返回骨架**。 |
| `disks` 为空 / 全部 `total <= 0` | **`null`** | 卡片的全部主题都拿不到，不该占一个格子 |
| 个别盘 `total` 非有限值或为 0 | 丢这一条，其余照画 | 无法计算占比，画成 0% 柱是编造 |
| `home === null`（会话目录读不到） | 第二行灰字改为 **web 进程**（`web 进程 525M · CPU 2.1% · 3h54m`） | `home === null` ≠ 空目录。**绝不**印文件数（那会被读成"0 个文件"）；此时"进程本身在吃多少"是有用的替代事实 |
| `proc.cpuPercent === null`（host 首个样本无增量） | 该处印 `—` | 契约的 `null` 语义；不写成 0.0% |
| `home.recentFiles` 为 0 | 正常印 `+0/h` | 这是真实读数（最近一小时没有写入），不是缺数据 |

**预览专用状态**：`example.sim.simSteps` 提供两态（`noHome: false / true`），点击卡片切到"会话目录读不到"的降级形态；`sim` 是 `simSteps` 的第一项（否则第一次点击是静默空操作）。`meta.sim` 只由预览通道传入，**rail 只传 `{ size }`**，线上不受影响（与 `task` 的空态用同一机制）。

## 8. 与既有卡的差异 / 遗留

**不重复**：既有 44 张卡（含 sys-cpu / sys-gpu / sys-rings / sys-board / sys-gpu-line）读的都是 `/api/sysinfo` 的**硬件半边**（CPU / 内存 / GPU），这张卡读的是新增的 `machine` 半边（盘 / 会话日志 / 宿主进程）。`grep machine` 在本仓库源码里除了 host 采样器与契约类型，没有任何消费者——这张卡是第一个。

**取舍与遗留**：

1. **柱子的墨量天然很低**（本机 C 22%、D 9% 剩余 → 12px / 5px 的小柱）。这是"剩余"口径的必然：工作机上的剩余永远是小比例。换来的是柱高 / 标签 / 语气 / 卡面文字**四者同向**。若车主更想看到"盘有多满"的饱满柱子，改一行 `ratio: 1 - d.ratio` 即可，但那时柱标签与灰字也应改成"占用"口径（否则卡面自相矛盾）——**这是产品口径的选择，不该由部件单方面决定**。
2. **会话日志没能放成 `sub`**（放进了 `headAfter.smallLines` 的第二行）：150px 高度预算下的唯一解，见 §4.2。内容完整，位置不同。
3. **柱标签带字节**（规格书写"label = 盘符"）：`bars` 没有数值列，不这么做的话每盘的 `67.1G / 300G` 在卡面上无处安放（规格书草图里它就在柱子右边）。
4. **>7 个固定盘**时柱标签 `C: 22%` 会开始贴到相邻列（标签实测约 32px，而 8 个盘的列宽 32.7px）。8 个固定盘在物理上不现实，且悬停 title 与柱高仍在，故不加第三档；若将来需要，按列宽分档即可。
5. **没有做点击/动作**：卡面不可点击（不占用 `cycle`，那是用量族池视图的位置），也没有 `corner` 按钮。
6. **需要共享层补的东西：无。** 本卡全部用既有原语（`headAfter.big` / `headAfter.smallLines` / `chart.bars` / `cardHint` / `simSteps`），没有新增渲染原语，也没有改共享文件。
7. 关于类型：`MachineInfo` 直接来自 `src/client/lib/contract/types.ts`（本 worktree 的快照里**已经有** `SysInfo.machine` 与导出的 `MachineInfo`），未使用局部镜像类型，`tsc --noEmit` 0 错。
