## 1. 这张卡回答什么问题

**"这台机器还有地方可写吗，以及 harness 自己在吃掉多少？"**

长跑的失败往往不是模型出错，而是两种运维事故：**盘满**（系统盘低于约 10% 时 Windows 明显降速并开始拒绝更新）与**会话日志膨胀**。既有的 44 张卡全部在回答"用了多少 token / 花了多少钱"，没有一张回答"跑它的这台机器还活着吗"。

```

│ 磁盘与自检                                     ← 蓝色标题 13px    │
│ D: 剩余 62.9G   DSH 会话日志 345M              ← 大数字 20px（最紧张的盘，带盘符）│
│                 近 1 小时新增 13 个文件         ← 灰字 10px（两行，压在大数字那 25px 里）│
│                                                                  │
│                  （贴底：bodyAnchor: 'bottom'）                   │
│ D: 剩余 62.9G / 652G                                     91%     │
│ ██████████████████████░░   ← 填充 = 已用（24 格分段条，红=危险档）│
│ C: 剩余 67.1G / 300G                                     78%     │
│ ███████████████████░░░░░   ← 填充 = 已用（蓝=正常档）            │
└──────────────────────────────────────────────────────────────────┘
```

- **大数字** = 剩余最少那块盘的**剩余量**（带盘符）。
- **灰字两行** = DSH 会话日志的体积 + 最近一小时的增速（**自解释**，不再有 `+13/h`）。
- **横条** = 每盘一行：左=**剩余量文字**，右=**已用百分比**，条=**已用量**（分 24 格）。
- 悬停整卡（`cardHint`）= dsh web 进程的 PID / RSS / CPU / 运行时长 + 会话日志**文件总数** +（盘多于 3 块时）被折叠的盘。

## 3. 数据来源

只读 `stats.sysinfo.machine`（`MachineInfo`；host 侧 `src/host/machine.ts`，磁盘 30s、会话目录 60s 各自 TTL）：

| 字段 | 口径 | 卡面上的位置 |
| --- | --- | --- |
| `disks[].mount` / `total` / `free` | `fs.statfs` 字节数（`free = bavail × bsize`），只含真实存在的固定盘，按盘符序 | 横条（一条一盘）＋行标签（左）＋右端已用 % |
| `home.sessionsBytes` | `$DSH_HOME/sessions` 递归文件大小之和（字节） | 灰字第一行 |
| `home.recentFiles` | 其中 mtime 在**最近 1 小时**内的文件数（增速信号） | 灰字第二行 |
| `home.sessionsFiles` | 上述递归文件数 | **悬停**（`cardHint`，原因见 §4.4） |
| `proc.pid` / `rss` / `cpuPercent` / `uptimeSec` | `dsh web` 进程自身（RSS 字节；CPU 为两次采样间的增量，**首个样本为 null**） | 悬停；`home === null` 时占灰字两行 |

**推导全在本目录内**（`index.ts`），没有往共享 `lib/` 加任何东西。

### 3.1 为什么自己写 `fmtBytes`（没有复用 `fmtTokens`）

`src/client/lib/format.ts` 的 `fmtTokens` **顶上只有 M**：652 GB 会被打成 `667648M`；它的"3 位有效数字"规则也是为 token 计数挑的，容量要到 G/T 才有意义。所以本地 `fmtBytes` 用 K/M/G/T（1024 进制，与 sys 家族的 `fmtGb` 同一约定），规则是 **<100 保留一位小数、≥100 取整**（`63.0G` / `300G`）。`fmtUptime` 同理不复用 `fmtDuration`（会把 3h54m 打成 `234m0s`）。

### 3.2 单位是 1024 进制，标签写 G

`fs.statfs` 报原始字节；÷1024³ 得到的其实是 GiB，但仓库既有的 `fmtGb`（sys-cpu / sys-gpu-line 在用）就这么标注，**同一栏里的两张卡不能对"G"有两种解释**，所以跟随现状。

### 3.3 `pct` 是"已用"，`label` 是"剩余"（本轮的反转）

`quotas.pct` 在这些原语里是**填充比例**——条填多少，右边就印多少。本轮按车主的要求把口径定成：**条 = 已用**，所以 `pct = usedPct(free/total)`，**文字侧（行标签）= 剩余字节**。旧的 `ratio: free/total`（条 = 剩余）正好相反，已删除。

## 4. 元素为什么这么摆（本轮四条意见逐条对应）

**这张卡是"量出来的"，不是排出来的。** 2×4 = 312×150 外框、310×148 客户区、内间距 12 → 内容区 **286×124**。全部数字为 gallery 真浏览器实测（`.tmp-measure.cjs`，非交付物）。

| 块 | 高度 | 说明 |
| --- | --- | --- |
| 标题行 | 16 | 13px × 1.2 |
| `headAfter` 行 | 4 + 25 | 4px 标准间距 + 20px 大数字行框；**灰字两行居中压在同一个 25px 行框里 → 零额外高度** |
| `quotas` 块 | 21×N + 5×(N−1) | 每行 = 9px 标签行(≈10.4) + 2px 间隙 + 9px 分段条 ≈ 21px，行距 5px |
| **2 盘**（车主的机器） | 45 + 48 = **93 / 124** | 余 32px（贴底后空隙落在头部与行之间） |
| **3 盘**（上限） | 45 + 74 = **119 / 124** | 余 6px，实测 `clientHeight = scrollHeight = 148`，**无溢出** |

### 4.1 大数字：`D: 剩余 62.9G`（保留，加了单位词）

车主说"大数字仍是**最紧张那块盘的剩余量**（带盘符），保留"。本轮额外补了**单位词** `剩余`：删掉第一行灰字后，裸的 `D: 62.9G` 就成了"需要一句解释的数字"（V3 §0.4 的硬门槛）——它可以是已用也可以是剩余。`剩余` 放在数字前（中文）／`free` 放在数字后（英文），两种语言都符合各自语序。

### 4.2 第一行灰字（`剩余 · C: 22% · D: 9%`）：**删掉**

车主："第一行灰色的小字和图表表达的是同一信息，重复了。" 确认：那一行逐盘复述的就是横条 + 右端 %。按"一个读数只出现一次"，**删掉重复的那半，只留图表**（原来它存在的理由是"柱只能给形状，占比必须是数字"——现在每一行的百分比就在条的正上方，这个理由消失了）。

### 4.3 图表：**横板 = `kind: 'quotas'`**（先读实现再决定）

读过 `render/charts/bars.tsx`、`barsV.tsx`、`quotas.tsx` 三个实现后的结论：

| 原语 | 实现事实 | 能否满足"横板 + 条=已用 + 文字=剩余" |
| --- | --- | --- |
| `bars` | 竖直柱：`height = 56×scale` 的柱区，柱宽 60%，**柱下**一行 9px 标签；只有 label 与 hover title 两个文字出口 | ✗ 结构上竖直，改成横排要动共享渲染器 |
| `barsV` | 同样竖直（"bars grow up from the floor"），高度写死等于热力图内容高 | ✗ 同上，且高度写死 |
| **`quotas`** | **每行：标签左 + 百分比硬右 + 24 格分段条在下一行**；`pct` = 填充比例，`filled = round(pct/100×24)` | ✓ **正是"横板"**，且官方额度族（`cc-credits`）已在用它，车主认识这个形状 |

选 `quotas`。**没有新原语、没有改共享文件**；标签仍由本部件写（`D: 剩余 62.9G / 652G`）。

### 4.4 第二行灰字（`会话日志 346 文件 · 345M · +13/h`）：**保留，但重写为两行自解释的话**

**取舍：保留而不是删掉**，三条理由：

1. **它是这张卡的另一半主题。** 卡名「磁盘与自检」，"自检"= harness 自己吃掉多少；`host/machine.ts` 的采样器专门为它走一遍会话目录。删掉之后 `sessionsBytes` / `recentFiles` 在本产品里**再无处可见**（§0 第 1 问：别处没有）。
2. **它不花高度。** `headAfter.smallLines` 是**居中压在大数字那 25px 行框上**的灰字块，两行 12.5px 正好塞满，**零额外高度**（`legend` 要另加 16px，`sub` 要另加 18px）。删掉它省不出任何像素给图表。
3. **改写成两行后它自己就说清楚了**：第一行说**是什么**（`DSH 会话日志 345M`），第二行说**那个数是什么意思**（`近 1 小时新增 13 个文件`）。旧的 `+13/h` 要读 host 源码才知道是文件数、字节还是会话数。

**为什么文件总数搬到了悬停**：大数字与灰字块共用**同一个 nowrap flex 行**，行内空间不足时 flex 会**按比例压缩两个子项**（都会打省略号，`figureEl` 自带 `text-overflow: ellipsis`）。实测（286px 行宽）：把总数留在卡上时英文是 `DSH session logs 345M · 346 files` = **160px**，加上大数字 131 + 间隙 4 = **295 > 286**，于是大数字被压到 127/131、那行被压到 155/160，**两处同时出省略号**（这就是"大数字绝不许丢字"的破口）。总数是三个 log 读数里唯一会无限增长的（五位数会出现），所以把它移到悬停；卡上只留**受机器容量约束**的两个事实。改后英文最长灰字行 122px + 大数字 131 + 4 = **257 / 286**，留 29px；中英四态（可读/不可读 × zh/en）实测**零省略号**。

### 4.5 行数上限 3 与排序：**最紧张的排最前**

`MAX_ROWS = 3`：3 行 74px ≤ 79px 可用，4 行 100px > 79px，卡片会**长出网格行**（rail 只设 `min-height`，超高不会被裁剪而是顶破布局，`CardBody` 的 tile-fits 守卫会把它标红）。**排序按紧张度升序**，于是上限只会折叠**最宽松**的盘，大数字所指的那块盘**永远在卡上**（按盘符顺序截断就可能把一块满盘藏起来）。`sort` 是稳定的，数值相等时保持盘符序，不会在两次 10s 轮询之间换来换去。被折叠的盘写进悬停：`另有 1 块盘空间更充裕：E: 剩 373G`（实测）。

### 4.6 贴底（`bodyAnchor: 'bottom'`）

仓库的 2×4 卡**都是贴底**的：`sys-board` 的环、`仓库脉搏` 的 figures、`任务` 的明细行全部挂在卡片底线上。本卡贴底后与它们共享同一条底线；只有 2 块盘时余量（32px）落在头部与横条之间——与 `仓库脉搏` 的版式同构。备选是顶对齐（横条紧跟头部，余量落在卡片下缘），实测**3 块盘时两者几乎无差别**（余 6px），所以选与邻居一致的那个。

### 4.7 右端百分比为什么是整数、为什么**向上**取整

档位判据是 `free < 10% / 20%`，而印出来的是**已用**。`Math.ceil` 的已用比例**永远不会夸大剩余空间**（告警该有的方向），并且让数字和颜色落在 90% 线的**同一侧**：红档 ⇔ `free < 10%` ⇔ `used > 90%` ⇒ 印出的已用 ≥ 91；黄档 ⇒ ≤ 90。另加 `1e-6` 守卫：恰好 90.00000000000001%（二进制浮点）不能被印成 `91%`。

## 5. 语气方向

**由本部件定义，绝不让渲染器猜**：判据是**剩余**空间，越少越危险——与 利用率（sys-cpu / sys-gpu / sys-rings）**极性相反**。条是**已用**画的，所以两句话是同一件事：`free < 10%` **就是** `used > 90%`，警报条是**满**的那根。

| 常量 | 值 | 依据 |
| --- | --- | --- |
| `FREE_DANGER` | `0.10` | Windows 在系统盘剩余低于约 10% 时明显降速，并开始拒绝更新 / 服务包 / 卷影副本——不是审美阈值 |
| `FREE_WARN` | `0.20` | 还来得及"计划清理"而不是"抢救"的那一档 |

- 条的颜色 = 档位（`quotas[].tone`：danger / warn / primary）；`primary` 是**中性品牌色**，不代表"好"。
- 大数字 = 同一个档位（`valueTone: 'danger'`）：**一个阈值，两处呈现**，卡面不可能自相矛盾。

## 7. 空态 / 降级行为

| 情况 | 行为 | 理由 |
| --- | --- | --- |
| `sysinfo` 缺失 / 非对象 / 老 host 没有 `machine` | `render` → **`null`** | 契约里 `skeleton` 的注释写明：加载骨架是**壳**的职责——widget 分不清"还在飞"与"答了但为空"。本卡不返回骨架 |
| `disks` 为空 / 全部 `total <= 0` | **`null`** | 卡片的全部主题都拿不到 |
| 个别盘 `total` 非有限值或为 0 | 丢这一条，其余照画 | 无法计算占比，画成 0% 条是编造 |
| `home === null`（会话目录读不到） | 灰字两行改为 **web 进程**：`dsh web 进程内存 525M` / `CPU 2.1% · 已运行 3h54m` | `home === null` ≠ 空目录。**绝不**印文件数（那会被读成"0 个文件"）；此时"进程本身在吃多少"是有用的替代事实 |
| `proc.cpuPercent === null`（host 首个样本无增量） | 该处印 `—` | 契约的 `null` 语义；不写成 0.0% |
| `home.recentFiles` 为 0 | 正常印 `新增 0 个文件` | 这是真实读数（最近一小时没有写入），不是缺数据 |
| 固定盘 > 3 块 | 只画**最紧张的 3 块**，其余进悬停 | 见 §4.5：绝不顶破网格行，也不藏起最紧张的盘 |

**预览专用状态**：`example.simSteps` 两态（`noHome: false / true`），点击卡片切到"会话目录读不到"的降级形态；`sim` 是 `simSteps` 的第一项。`meta.sim` 只由预览通道传入，**rail 只传 `{ size }`**，线上不受影响。

**接线骨架（`manifest.skeleton`）**：`{ "shape": "quotas", "count": 3 }`。本轮从 `figures`（一排 4 个短块 = 横向排布）改成 `quotas`（N 条堆叠横条）——卡身现在是堆叠的额度行，骨架必须长得像它自己（V2 §3）。

## 8. 与既有卡的差异 / 遗留

**不重复**：既有卡（含 sys-cpu / sys-gpu / sys-rings / sys-board / sys-gpu-line）读的都是 `/api/sysinfo` 的**硬件半边**（CPU / 内存 / GPU），这张卡读的是 `machine` 半边（盘 / 会话日志 / 宿主进程）。`grep machine` 在本仓库源码里除 host 采样器与契约类型外没有别的消费者。

**取舍与遗留**：

1. **两块盘时卡片下半部有 32px 余量**：`quotas` 的行高由原语写死（9px 标签 + 2 + 9px 条 + 5px 行距），2 行填不满 79px。用 `bodyAnchor: 'bottom'` 把余量收进头部与横条之间（与 `仓库脉搏` 同构）；3 块盘时只剩 6px。**不动共享渲染器**的前提下这是唯一解。
2. **每组都印了"剩余"**：大数字 `D: 剩余 62.9G` 与它自己那一行 `D: 剩余 62.9G / 652G` 有重复。这是车主两条要求（"大数字保留" + "文字表示剩余"）的直接后果：大数字是**唯一要行动的那个数**，行是**全盘明细**。被删掉的是"逐盘复述一遍"的那半（§4.2）。
3. **右端百分比是"已用"**，与左侧文字的"剩余"是两个量（原语只给这一个文字出口，且它必须等于填充比例）。行的结构是官方额度行的样子：左边说是什么，右边是条自己的读数。
4. **`home.sessionsFiles` 在悬停**（§4.4）：卡面放不下第三个无界读数。
5. **没有做点击/动作**：卡面不可点击（不占用 `cycle`，那是用量族池视图的位置），也没有 `corner` 按钮。
6. **需要共享层补的东西：无。** 全部用既有原语（`headAfter.big` / `headAfter.smallLines` / `chart.quotas` / `bodyAnchor` / `cardHint` / `simSteps`），没有新增渲染原语，也没有改共享文件。
