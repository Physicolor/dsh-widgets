# sys-services — 本地依赖（本机关键端口 + 代理出口）

## §0 审计

> 这一节是**交付物**，不是背景介绍。车主的原话是：「本地服务其实还可以吧，但是这个本地服务指的是什么呢？本地大模型服务？本地进程？设计出来是给什么受众什么使用场景呢？」下面三小节正面回答这三问，0.4 是 WORKER-BRIEF-V3 的六问，0.5 是边界与限制。

### 0.1 「本地依赖」到底指什么

它指**这台机器上，你的活依赖的那些「本地端点」，以及能不能真的出网**。具体只有两类：

| 类 | 内容 | 证据 |
| --- | --- | --- |
| ① 本机监听的关键端口 | host 侧写死的四个：`DSH web`(3080)、`Ollama`(11434)、`LM Studio`(1234)、`Proxy`(10808) | `node:net` TCP 握手（回环 ~0.2–2ms） |
| ② 代理出口 | `127.0.0.1:10808` 背后**能不能把流量送出去** | host 侧一条绝对 URI GET（`GET http://www.gstatic.com/generate_204`），本机中位 ~1.3s |

**它不是本地进程。** 进程表是另一张卡（`sys-procs` / 内存大户）：这张卡不列进程，即使 Ollama 本身是一个进程 —— 它问的是「那个端口还在不在听」，不是「谁在吃内存」。

**它不是通用服务监控。** v1 只探 host 写死的那四个端口，且只做 TCP 握手（代理例外，它有真正的出口 GET）。MCP server 的健康、CUDA / 驱动版本、网络带宽、模型额度/质量，全部不在它的范围内。

**改名就是为这一问服务的**：`本地服务` → **`本地依赖`**（`Local Services` → `Local Dependencies`）。原名里没有主语，读者分不清它列的是进程、模型运行时，还是所有在听的东西。

**默认只显示真正相关的两个**：`DSH web` 一行 + 头部的出口结论。`Ollama` / `LM Studio` 是**可选行**（默认关，见 §6）—— 一台不跑 LM Studio 的机器上，那行永远是红色「未运行」，那是卡片**自己制造的假警报**，也正是车主看到的那张图的问题。

### 0.2 受众与使用场景

**受众**：在这台机器上长跑 agent 的人（会话、子代理、后台任务都在本机；`git` / `gh` / 联网抓取全走 `127.0.0.1:10808`）。

**场景**：
- **「一切都慢」时的第一刀**：大数字直接给结论。`出口不通` ⇒ 慢的不是模型、不是 DSH，是这台机器出不去网；`出口正常` ⇒ 从别处找原因（模型/额度/磁盘）。
- **「某个依赖挂了」时定位到行**：`DSH web` 行掉线 ⇒ 这个 Web UI 自己的端口没了（页面还能动说明是别的实例）；开了 `Ollama` 开关后，`Ollama 未运行` ⇒ 本地模型推理一定失败。
- **「检测中」也是一句话**：`ok === null` 是探针还在飞（stale-while-revalidate），印「检测中」而**绝不是**故障 —— 把「还没测完」印成故障，车主会照着错误结论去修东西。

**它明确不管的场景**：MCP server 健康（没有任何探针）、CUDA / 驱动（`sys-gpu` / `sys-gpu-line`）、网络带宽（`sys-net`）、额度与限流（`cc-*` / `window-forecast`）、模型质量、localhost 上除这四个端口以外的任何东西。

### 0.3 与既有卡的分工（逐条）

| 既有卡 | 它回答 | 本卡的边界 |
| --- | --- | --- |
| `sys-net`（网络吞吐） | 网卡的**字节速率**（rx/tx 差分）：链路忙不忙 | 本卡测的是**可达性**，不是带宽。代理在传 10MB/s 还是 1KB/s 与本卡无关；本卡只回答「一条请求能不能穿过去、花多久」 |
| `sys-procs`（进程内存占用） | 按工作集排序的**进程** | 本卡不列进程，也不看内存。Ollama 进程在不在不是本卡的内容，「11434 端口在不在听」才是 |
| `sys-cpu` / `sys-gpu` / `sys-rings` / `sys-board` / `sys-gpu-line`（sysinfo 家族） | 本机**资源占用**：利用率 / 显存 / 温度 | 资源 vs 可达性：机器再闲，代理挂了也什么都干不了；机器再忙，只要出口通，本卡就是绿的 |
| `sys-disk` / `sys-power` | 磁盘剩余 / 供电 | 无交集 |
| DSH 官方 UI（输入框的模型与推理档、权限选择器） | 会话配置 | 无交集：没有任何官方位置显示代理出口 |
| 名叫 `localhost` 的卡 | **不存在** | 若有人以为本卡是「本机端口总览」：不是。host 只探四个写死的端口；本卡的 `DSH web` 行说的是「这个 Web UI 的端口还在不在听」，不是 UI 状态 |

### 0.4 V3 六问

1. **别处有没有更方便地展示？** 没有。代理出口的结论在 rail、组件市场、官方设置页里都不存在；而它一旦挂了，表现是「一切都慢」—— 这是本卡唯一不可替代的价值。
2. **有没有功能高度重合的既有组件？** 见 0.3。最接近的是 `sys-net`（同属 device 组，都关于网络）：**窗口**（本卡 = 一次探针 / TTL 60s；sys-net = 两次计数采样）、**范围**（本卡 = 端口的可达性；sys-net = 每张网卡的速率）、**单位**（本卡 = 状态词 + 毫秒/秒；sys-net = B/s）、**时态**（本卡 = 现在能不能出去；sys-net = 刚才传了多少）。四项全部不同。
3. **不读文档怎么分清两张？** 名字「本地依赖」已经说了主语；大数字是**词**（`出口正常`/`出口不通`/`检测中`），不是任何别的卡的百分比；灰字第一句是它的读数（`出口 1.3s`）。三条自己回答「我是哪个」。
4. **大数字是什么单位、什么范围、什么时间点？** 它根本不是数字：是**本机出网结论**的三态词。范围 = 这一台机器 + 本机代理端口；时间点 = 最近一次完成的出口探针（host 侧 TTL 60s，`ok === null` 时表示这一次还没回来）。
5. **应该一直在，还是可以消失？** 用户**主动装**它（`defaultInstalled: false`，见 manifest）。`stats.host` 缺失或 `services === []` → `render` 返回 `null`（没有任何端点就没有主题，这是启动瞬间的加载态，由 shell 的骨架屏承载）；一旦有 `services` 就常显，**包括出口检测中**这种「没结论」的时刻。配置关掉的端点不出现 —— 那不是「缺数据」，是用户的选择。
6. **颜色有没有被赋予用户能说出的含义？** 有，只给**等级**：`出口不通` → `danger`（真故障）；`检测中` → `muted`（未知不是故障）；`出口正常` → **不染色**（好状态不需要绿色，绿在这里会变成装饰）；掉线的端点行 → `danger`。没有任何「无等级含义」的量被染色。

### 0.5 已知限制（v1 边界）

1. **端口表目前是 host 侧写死的四个**（`src/host/overview.ts` 的 `SERVICE_TARGETS`），用户不能加任意端口。本卡能配的只有「这两个可选端点要不要出现」。扩展方式写在 §10（host 接受 `?ports=`），**本次不做**。
2. **「端口在听 ≠ 服务可用」仍未解决**（代理是唯一例外）：四个端口只做 TCP 握手，一个监听中但已经半死的 Ollama 一样会显示「通 · 2ms」。要真的判断可用性需要 HTTP 探针，见 §10。
3. **TCP 握手不能证明代理能出网**：本机 xray 对**不存在的域名**也回 `200 Connection established`（2026-09-29 实测）。所以出口结论只取 host 侧那条绝对 URI GET 的 `ok`；`tcpMs` 从来不是结论。

## 1. 这张卡回答什么问题

**这台机器上，你的活依赖的那些东西还在不在 —— 关键端口还听不听，以及现在能不能真的出网**。一句话把「本地端点挂了」和「代理挂了但没人看得见」两类故障摊在一张卡上。

## 2. 卡面草图（2×2）

默认形态（Ollama / LM Studio 关，只有两个主角：DSH web + 代理出口）：

```
┌ 本地依赖 ─────────────────────┐
│ 出口正常                       │  headAfter.big：代理出口结论（三态词）
│ 出口 1.3s                      │  legend：结论背后的读数
│ ────────────────────────────── │  breakdown 自带的发丝分隔线
│ DSH web            通 · 1ms    │  唯一的默认明细行
└───────────────────────────────┘
```

开了 `Ollama`（+ `LM Studio`）开关后，可选行出现（`LM Studio` 那台没跑 → 红）：

```
┌ 本地依赖 ─────────────────────┐
│ 出口正常                       │
│ 出口 1.3s                      │
│ ────────────────────────────── │
│ DSH web            通 · 1ms    │
│ Ollama             通 · 2ms    │
│ LM Studio             未运行   │  ← 只有你开了它才出现（开之前根本没有这行）
└───────────────────────────────┘
```

出口三态（大数字 + 灰字是**结论 + 证据**，不重复同一个词）：

| 状态 | 大数字 | 灰字 |
| --- | --- | --- |
| 正常 | `出口正常` | `出口 1.3s` |
| 不通 | `出口不通`（红） | 失败码（`ECONNREFUSED`）或代理端口握手（`代理 0.3ms`） |
| 检测中 | `检测中`（灰） | `代理 0.2ms`（端口握手回来了，出网结论还在飞） |

`services` 为空数组 / `stats.host` 缺失 → `render` 返回 `null`（整卡不出现）。

## 3. 数据来源

只读 `stats.host`（`/api/host/overview` 路由，本仓库 `src/host/overview.ts` 采集）：

| 字段 | 口径 |
| --- | --- |
| `host.services` = `HostServiceProbe[]` | `node:net` TCP 探活，**永远有值**（可能是空数组）。顺序固定：`DSH web`(3080) / `Ollama`(11434) / `LM Studio`(1234) / `Proxy`(10808)。`ms` = 握手毫秒，失败为 `null` |
| `host.proxy` = `HostProxyHealth \| null` | `tcpMs` = 到代理端口的握手；`egressMs` = **绝对 URI GET** 穿过代理的端到端耗时；`ok` = 该测量的结论；`error` = 失败码 |
| `host.ts` / `net` / `power` / `procs` | **不读**（本卡不展示网速/电源/进程） |

**`tcpMs` 单独不能当结论（本卡存在的理由）**：本机 xray 对**不存在的域名**也回 `200 Connection established`（2026-09-29 实测）。所以「端口在听」不等于「能出网」，真判据只有 `ok` —— 它由 host 侧那条绝对 URI GET 产生。`ok === null` = 探针还在飞（stale-while-revalidate），**不是故障**，印「检测中」。

`null` / `[]` / `—` 的分工：

| 情形 | 呈现 |
| --- | --- |
| `host` 缺失 或 `services === []` | `render` 返回 `null`（这张卡的全部内容就是这些端点，没有端点就没有主题） |
| `host.proxy === null` 或 `proxy.ok === null` | 大数字 = `检测中`（`muted`）；灰字 = `代理 {tcpMs}`，没有握手读数时**不印灰字**（宁缺勿造） |
| `proxy.ok === true` | 大数字 = `出口正常`（不染色）；灰字 = `出口 {egressMs}` |
| `proxy.ok === false`，码 ≤16 字符 | 大数字 = `出口不通`（`danger`）；灰字 = **码本身**（`ECONNREFUSED`） |
| `proxy.ok === false`，码 >16 字符 / 无码 | 大数字 = `出口不通`；灰字 = `代理 {tcpMs}`，完整码在悬停（`cardHint`） |
| `up === false`（且该端点被显示） | 该行 value = `未运行` + `tone: 'danger'`，**不印 `—`**（"没在听"是确定的结论，`—` 表示"没测到"） |
| `up === true` 但 `ms === null` | value = `通`（只有状态，没有延迟）—— 这一情形实际不可达（探针只在连接成功时才给 ms），代码里仍然分支，避免以后改动悄悄印出 `通 · null` |

## 4. 元素为什么这么摆

- **大数字 = 代理出口的结论词**（`出口正常` / `出口不通` / `检测中`）。默认形态下通用本体只剩一个端口 + 出口，`N / M` 计数没有任何意义（分子分母都在说"1/2"，而 `1` 就是 DSH web 自己）；而**一个词不需要解释**（BRIEF V3 §0.4）。它也是这张卡唯一不可替代的读数。用 `headAfter.big`（不是 `value`）：`value` 是正文数字，在有 `headAfter` 的卡上会被推进正文重复渲染一次。
- **灰字 = 结论的证据，不是结论本身**：`出口正常` 下面是 `出口 1.3s`（读数）；`出口不通` 下面是失败码或代理端口握手。**同一句话不印两遍**（V3 §3「一个读数只出现一次」）—— 所以灰字里不会再出现 `出口不通` / `检测中` 这两个词。
- **`检测中` 时灰字是端口的 TCP 握手**（`代理 0.2ms`）。出口结论还没有的时候，唯一诚实的读数是那个已经回来的握手；结论一到就撤掉，因为 `egressMs` 本身就是穿过代理的端到端测量，再印握手等于用宝贵的一行复述一个被结论支配的数。
- **代理不做明细行**：它的存活（端口）与结论（出口）已经整个占据头部，再列一行就是一件事说两遍（`sys-procs` 对它的 #1 进程用同一套纪律）。
- **明细行标签左、数值右，贴底**（`bodyAnchor: 'bottom'`）。行数上限 `MAX_ROWS = 3`：头部已是三级阶梯（标题 16 + 4 + 数字 25 + 2 + 灰字 12），第四行会越过 126px 内容盒。默认形态只有一行 —— 那是**设计**，不是空：关掉的端点不占位。
- **`up` 的延迟统一带单位**（`通 · 1ms`），与"这一行是状态 + 读数"的读法一致；`未运行` 单独成词，因为它没有读数。
- **不加 `headRing`**：环是"占比"的语言，这里没有占比；出口三态是离散结论，环会把一个词画成一个角度，凭空造出"完成了多少"的暗示。
- **`cardHint`（悬停）**：`TCP 在听不等于能出网` 这条纪律，加上失败时的**完整** error 串。

### 延迟的格式化（`fmtMs`）

两个量的量级差三个数量级：回环握手 0.2–2ms，穿代理的出口 GET ~1.3s（2026-09-29 实测）。

- `< 1ms` → 一位小数（`0.2ms`），**永不印成 `0ms`**（那是"没测到"的读法，而它恰恰是本机最常见的读数）；
- `≥ 1000ms` → 换秒（`1.3s`），与 `fmtDuration` 对工具耗时的处理同形。

### 失败码的长度预算（本次在真实卡片里实测，不再沿用上一版的估算）

legend 是一行 `nowrap` + `ellipsis` 的灰字，150px 卡里它的内容盒**实测 124px**（2026-09-30，在 gallery 页用卡片自己的字体量的）。上一版把码包成 `出口不通（码）`，那 40px 的包装把预算压到 9 个字符，`ECONNRESET` 就被切掉了。

现在结论搬进了大数字，灰字只剩**光秃秃的码**，同一套测量给出的数字是：

| 码 | 字数 | 实测宽 | 结论 |
| --- | --- | --- | --- |
| `proxy 0.2ms` | 11 | 50.0px | 放得下 |
| `ECONNREFUSED` | 12 | 78.9px | 放得下 |
| `CONNECTION_RESET` | 16 | 100.6px | 放得下（余 23px） |
| 预算 | — | **124px** | 即 `ERROR_CODE_CHARS = 16` |

所以预算是 **16 个字符**（`ERROR_CODE_CHARS`）——它覆盖了 host 侧能产出的最长码。它是字符数而不是像素宽，因为 `render` 是纯数据函数，拿不到字体度量。超过预算时灰字退回**代理端口的握手**（`代理 0.3ms`；此时连握手都没有就不印这一行），**完整 error 串始终在悬停里**。错误串还会先取「命名 token」：`connect ECONNREFUSED 127.0.0.1:10808` → `ECONNREFUSED`（`connect` 是噪声动词，目标地址那半截又长又与卡上已有的端口重复）。

## 5. 语气方向（tone 的语义由本部件决定）

**头部只为一个主语说话 —— 代理出口结论**，所以只有它给头部染色：

- `ok === false` → 大数字 `valueTone: 'danger'`；
- `ok === null` → 大数字 `valueTone: 'muted'`（"我还不知道"不是故障）；
- `ok === true` → **不染色**（好状态不需要绿色装饰）；
- 端点掉线的**行** → `tone: 'danger'`，**不会**把大数字染红。

这一条是本轮改版的实质修正：上一版把「有几个端点在听」当大数字，所以**任何一个端点掉线就染红整个大数字** —— 一台没装 LM Studio 的机器于是永远顶着一个红色大数字。现在大数字只对出口负责，掉线的端点自己红（归属清楚）。

规则与阈值全部在 `index.ts` 里，渲染器从不猜。

## 6. 配置项

两个开关，**默认都关**（`default: false`）。关掉的端口**不出现那一行**——不是灰掉、不是印 `—`，因此不会再出现"未运行"的假警报。

| key | 类型 | 默认值 | 可选值 | 作用 |
| --- | --- | --- | --- | --- |
| `showOllama` | `toggle` | `false` | 开 / 关 | 是否显示 `Ollama`(11434) 那一行；hint = 「不跑本地模型就别开：关掉的端口不显示那一行，也就不会有「未运行」的假警报」 |
| `showLmStudio` | `toggle` | `false` | 开 / 关 | 是否显示 `LM Studio`(1234) 那一行 |

- 没有 `text` / `textarea` / `mode` / `metrics` / `max` 一类的字段；开关以外无配置。
- 读法：配置由 shell 合并进 `stats`（`cardConfigs[instance]` 最后合并，见 `runtime/live-stats.ts`），只有显式 `true` 才显示 —— 没配过的卡和关掉的卡是同一种读法。
- 车主逐项测法：组件配置里开 `显示 Ollama` → 卡面立刻多出 `Ollama` 行；关掉 → 那一行**整行消失**（不是变灰）；`LM Studio` 同理。

## 7. 空态 / 降级行为

| 条件 | 行为 |
| --- | --- |
| `services === []` 或 `host` 缺失 | `render` → `null` |
| 可选端点开关为关 / 未配置 | 该端点**没有行**（不是灰行、不是 `—`） |
| `services.length < 3` | 有几行画几行（不补 `—` 占位：端点是真枚举，不是可选项） |
| `host.proxy === null` | 大数字 = `检测中`，无灰字（没有任何读数可印） |
| `proxy.ok === null` | 大数字 = `检测中` + 灰字 = 已知时的 `代理 {tcpMs}` |
| `proxy.ok === false`，码 ≤16 字符 | 灰字 = 码本身 |
| `proxy.ok === false`，码 >16 字符 / 无码 | 灰字 = `代理 {tcpMs}`（无握手则不印），完整码在悬停 |
| `up === true` 且 `ms === null` | value = `通` |
| 行数 > 3（未来 host 加端口） | 只画前 3 行（头部 + 3 行 = 高度预算） |

## 8. 与既有卡的差异

`grep` 过现有 55 个单元：读 `stats.host` 的只有四张（`sys-net` / `sys-power` / `sys-procs` / 本卡），而 `/api/host/overview` 的四个**互不相交的 section** 正好一人一块 —— `host.net`（带宽）/ `host.power`（供电）/ `host.procs`（进程）/ `host.services` + `host.proxy`（本卡）。**没有任何别的单元读 `services` 或 `proxy`**（grep 确认），本卡是这两块唯一的主人。

`sysinfo` 家族（`sys-cpu` / `sys-gpu` / `sys-rings` / `sys-board` / `sys-gpu-line`）读的是另一条线 `stats.sysinfo`（本地采样），与 `stats.host` 不是同一个数据源；语义上也是两类：

- `sysinfo` 家族 = **资源占用**（这台机器有多忙）；
- `sys-services` = **可达性**（这台机器还连不连得上东西，以及能不能出网）。

与 `sys-net` 的四面差异（窗口 / 范围 / 单位 / 时态）写在 §0.4 第 2 问；与 `sys-procs` 的差异写在 §0.3。

`defaultInstalled: false`：这是新增的可选项，用户自己决定装不装；**装了以后**它就常显（包括检测中），不会因为数据缺失弹进弹出。
