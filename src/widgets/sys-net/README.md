# sys-net — 网络吞吐

## 1. 这张卡回答什么问题

**「装依赖、拉模型、传大文件的时候，为什么这么慢？」**——本机网卡此刻真实的收发速率。
sys 族已经有 CPU / 内存 / GPU / 磁盘，网络是唯一完全没有仪表盘的资源，而它恰好是
「所有读数都闲着、下载却在爬」时唯一能解释原因的读数。

## 3. 数据来源

| 读的字段 | 口径 |
| --- | --- |
| `stats.host?.net.rxBps` | 所有网卡的下行合计，**字节/秒**（host 两次计数采样差分） |
| `stats.host?.net.txBps` | 所有网卡的上行合计，字节/秒 |
| `stats.host?.net.adapters[0]` | 最忙网卡（host 已按 `rxBps + txBps` 降序排好，取首个） |
| `stats.hostError` | **不读**（见 §7 的降级说明） |

- 速率格式化是本目录自己的 `fmtRate`：二进制步进（1024），单位 `B/s / KB/s / MB/s / GB/s`。
  **不能用 `fmtTokens`**：那是 token 量级格式化器（步进 1000，无单位，因为 token 数不需要
  单位），而速率离开单位就没有意义，且同一张卡上不能出现 1000 进制与 1024 进制并存
  （sys 族的 `fmtGb` 就是 `1024**3`）。
- 数值是**双精度浮点**，`fmtRate` 做了 `NaN / 负数 → 0` 的兜底（host 已把计数重置钳成 0）。
- **合计包含虚拟网卡与回环**（`Win32_PerfRawData_Tcpip_NetworkInterface` 的全部实例，
  host 未过滤）：本机常见的 UF 上看到 `Loopback Pseudo-Interface 1` 有流量就是本机回环。
  这是 host 的口径，本卡不改。
- `net` 切片靠**两次计数器差分**得出，所以**第一次调用必然是 `null`**（只存下基线）。

## 4. 元素为什么这么摆

- **大数字 = 下行**：agent 的等待几乎都是「下载」（依赖、模型权重、网页抓取）；上行通常
  小一个量级，所以它花的是灰字与明细行，而不是 20px 那一档。
- **灰字 = 上行 + 最忙网卡短名**：一行把两个「顺带要知道」的事说完（`↑ 92 KB/s · Wi-Fi 6E`）。
  短名取的是**技术标识**（`Wi-Fi 6E`）而不是厂商（`MediaTek`）——本机的三张网卡厂商各不相同，
  但没人用厂商指代网卡。
- **明细三行 = 下行 / 上行 / 最忙**：三行永远是三行（缺读数印 `—` + `muted`），行数不随数据
  变化。前两行与大数字/灰字同值，这是规格书 §8 规定的卡面（大数字是「一眼读数」，明细是
  「带标签的确切值」），代价是两处重复，见 §8。
- **贴底（`bodyAnchor: 'bottom'`）**：与 `cache` / `tool` 同一姿势——明细坐在卡片地板上，
  而不是把节省下来的高度留在下面。

### 网卡名的截断策略（本条是实测算出来的，不是拍的）

适配器名是 `MediaTek Wi-Fi 6E MT7922 160MHz Wireless LAN Card`（48 字）。而 `breakdown`
的三行**共用一套 `1fr auto` 列轨**：最长的 value 决定 value 轨宽，标签列拿剩下的——而标签列
自带 14px 的右缘淡出遮罩（`breakdown.tsx`）。实测（`.tmp-probe-breakdown.mjs`，克隆真实
value 单元格以复用同一字体与 tabular-nums）：

| | |
| --- | --- |
| 网格宽 / 列间距 / 标签自然宽 | 124px / 8px / 20.7px |
| 标签列下限 | 20.7 + 14 = **34.7px** |
| 由此 value 轨上限 | 124 − 8 − 34.7 = **81.3px** |

在这个预算下测量四张真实网卡名（`…` 前 n 个字符的实宽）：

| 名字 | 13 字 | 14 字 | 15 字 |
| --- | --- | --- | --- |
| `MediaTek Wi-Fi 6E …` | 79.2 | 84.2 | 87.8 |
| `Hyper-V Virtual …` | 73.0 | 79.5 | 85.3 |
| `Loopback Pseudo-…` | 78.7 | 85.1 | 91.8 |
| `Realtek PCIe GbE …` | 72.2 | 75.2 | 82.9 |

→ `NAME_MAX = 13`（最宽 79.2px，留 2px）。**规格书草图的 18 字 `MediaTek Wi-Fi 6E…` 实测
94.3px**，会把 下行/上行/最忙 压进自己的淡出遮罩里（第一版截图里三个标签都只剩半个字）。
另外先做一步 `dropVendor`：名字从技术标识开始（`Wi-Fi 6E MT7922 160MHz…`），因为
13 字预算里，`MediaTek Wi-Fi 6E…` 只能买到厂商，`Wi-Fi 6E MT7…` 才买得到技术+芯片型号。
没有技术标识的纯 OEM 名（`Realtek PCIe GbE Family Controller`）整名照旧截断。

同一条预算也管着**英文标签**（实测：标签列 39.2px，淡出边界 25.2px）：`Down` 28px、
`Up` 13.9px、`Busiest` 33.8px —— 所以第三行的英文用 **`Busy`**（22.4px，干净）。
`Down` 的右端落在淡出带的最后 2.8px（≈80% 不透明），肉眼不可辨，保留（它是「下行」最直接的
英文对应词，换成 `Rx` 会与中文语域不一致）。这是本卡唯一一处为版面而选词的地方。

## 5. 语气方向

**不染色**——吞吐量是读数，不是判决：2 MB/s 不叫「好」，0 B/s 也不叫「坏」（机器闲着是健康的）。
环（`headRing`）同样不用：环是「占比」的语言，速率没有分母。本卡自己拥有的阈值是**显示预算**
（`NAME_MAX`、legend 短名），不是颜色。唯一的 tone 是「最忙」行在 host 报得出吞吐、却没有
任何网卡条目可指名时（两张样本之间网卡被重新枚举）的 `muted` + `—`。
这条方向由本部件决定并写在这里；渲染器不猜。

## 6. 配置项

无（第一版）。`sizes: ['2x2']`。

## 7. 空态 / 降级行为

| 情形 | 表现 |
| --- | --- |
| `stats.host?.net === null`（还没有两个计数样本） | `render` 返回 **null**（壳按 `source: 'sys'` 画骨架） |
| `net.adapters` 为空数组 | 照常渲染；「最忙」行印 `—` + `muted`，legend 只有 `↑ <速率>` |
| 速率真的是 0（两个样本、无流量） | **照常渲染** `0 B/s`——零流量是合法读数，不是缺失 |
| `fmtRate` 收到 NaN / 负数 | 按 0 处理 |
| `stats.hostError`（host 路由整体没答） | **本卡不区分**：`net` 也是 null，于是同样是 null/骨架。若要区分「dsh web 没重启」，需要主 Agent 在共享层给出约定（见结案 §6） |

## 8. 与既有卡的差异

- 加入本卡之前，注册表里的 **43 个部件没有任何一张读 `stats.host`**（本卡是
  `/api/host/overview` 家族的第一张）：所有既有网络信息为零。`sys-cpu` / `sys-gpu*` /
  `sys-rings` / `sys-board` 读的是 `stats.sysinfo`（CPU/内存/GPU），`counts` / `tokens`
  读会话投影。
- 与 `cache` / `tool` 的版式相同（头部三级阶梯 + 贴底三行明细），但**没有环、没有 tone**：
  这两张卡的环与红绿是「占比/失败」的语言，速率两样都不沾。
- 唯一的重叠风险：大数字（下行）与「下行」行、legend 的上行与「上行」行**同值**。这是
  SPECS §8 卡面规定的「一眼读数 + 带标签明细」写法；若要按仓库「一件事不说两遍」的纪律去掉
  重复，改法是把三行换成 `上行 / 最忙 / 网卡数`（一行代码的改动），等车主定夺。
