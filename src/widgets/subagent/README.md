# subagent — 子代理

> 第三批部件（Wave 1，2026-09-29 **修订轮**），`order: 84`，`group: system`，尺寸仅 `2x2`，无 `source` / `skeleton`。
> 本轮按车主对卡面的直接反馈重做职责：**只回答「派出去的是些什么」（身份）**，不再以"活了多久"为主角，并**去掉全部颜色**。

## §0 审计（开工前强制六问，WORKER-BRIEF-V3 §0）

**1. 这个信息是不是已经在别处更方便地展示了？**
没有。在本仓库里 `subagentCatalog` 被 grep 到的地方只有 `contract/types.ts`（类型）、`data/session-stats.ts`（`normalizeSubagents` 归一化）、`data/collector.tsx`（填入 `stats.subagents`）与这张卡——**它是该投影唯一的消费者**。
产品自身的 UI（输入框的模型/推理档、权限选择器、页头、设置页）都不显示子代理的名册；派子代理的那次工具调用会留在对话流里，但"一共派了几个、哪几个是可持续的、最近一个是誰"没有任何常驻位置。**结论：做，但只做身份那一半。**

**2. 有没有功能高度重合的既有组件？**
有一个真实重合：**`jobs` 的 `kind` 里就有 `subagent`**，两张卡都在回答"有几个子东西在跑"。逐项差异（窗口 / 范围 / 单位 / 时态）：

| 卡 | 数据面 | 有状态吗 | 大数字 | 回答的问题 | 时态 |
| --- | --- | --- | --- | --- | --- |
| **`subagent`（本卡）** | `subagentCatalog` 投影 | **没有**（只有 id / createdAt / mode / label / activeMs） | **派出去的总数**（个） | 「派出去的是些什么」（身份） | 名册——会话至今派过谁 |
| `jobs` | `jobsBySession` 镜像 | **有**（running / stopping / completed / killed / failed） | 运行中 + stopping 的个数 | 「有没有活正在占着机器」 | 运行时——此刻 |
| `task` | `todos` 投影 | 有 status，但是待办自身 | 进行中条数 | 「我接下来干什么」 | 计划 |
| `trajectory` | `trajectory[]{kind,ms}` | 无 | 无（三色泳道） | 「每一步是什么节拍」 | 过程回放 |
| `counts` | `turns` / `steps` | 无 | 轮次数 | 「会话跑了多少拍」 | 计数 |
| `tool` | `tools` 折叠 | 有 `running` | 累计耗时 | 「本会话自己的工具调用花了多久」 | 统计 |

**结论：分化，不合并。** `jobs` 管运行时状态（它读得到 `status`），本卡管身份（它读不到状态）。合并会把两个数据面塞进一张 150px 卡，并且必然要伪造其中一个的读数。

**3. 用户不读文档，怎么分清这两张？**
- **名字**：`子代理`（Subagents）vs `后台作业`（jobs；本轮由那张卡自己改名为 `后台任务` / Background Tasks）。
- **大数字的单位**：本卡是"**派出去过几个**"（无状态，历史名册）；`jobs` 是"**此刻占着机器几个**"（运行中）。两者的数字会不一样，且理由不同。
- **灰字第一句自带主语**：本卡 `最久活跃 36m12s`（已记账活跃时长），`jobs` `最久 12m4s · 共 4 个`（正在运行的时长）。
- 卡面**任何位置都不出现「运行中」**：投影没有状态字段，写了就是编造。两条可复核的判据——`manifest.json` 的 6 个 `card.subagent.*` 与 2 个 `widget.subagent.*` 文案里没有这个词；并且 render 的**输出**（`WidgetRenderOut` JSON）在 11 组合成目录 × 2 locale 的扫描中都没有命中 `run|运行`。

**4. 这个大数字是什么单位、什么范围、什么时间点？**
单位「个」；范围 = **本会话的直接子代理**（`subagentCatalog` 的全部条目，不含孙代理、不含工具调用、不含后台作业）；时间点 = **本会话至今的名册**——它不是一个"此刻"的读数，也没有"正在"的含义。`4` 读作"这个会话一共派出过 4 个子代理"，不需要任何解释。

**5. 它应该一直在，还是可以消失？**
**可以消失**——`subagents === null`（该部署没有这个投影）与 `[]`（投影在，但从没派过）都返回 `null`，整卡不占格子。
理由：这张卡是**新增的可选卡**（`manifest.defaultInstalled: false`），用户**主动装进 rail** 之前它永远不会出现；而没有子代理是**每个会话的默认状态**，不是"刚刚结束"的新闻，也不是"用户正在等的那个结论"。
这与 `jobs` 的相反选择是同一把尺子的两端：`jobs` 的空列表是**用户正在等的答案**（"后台作业全清了"本身是确认），本卡的空目录只是"这次没派活"。
**已知代价（诚实记录）**：装进 rail 之后，本卡会随子代理的有无出现 / 消失，rail 的 deck 形状随之变化。若车主更在意布局稳定，改成安静空态（`{ title, value: '暂无子代理' }`，与 `task` 的空态同一姿势）是一行改动——见结案报告第六段。

**6. 颜色有没有被赋予一个用户能说出的含义？**
**没有，所以本轮一个颜色都不用。** 绿 / 黄 / 红只表示**危险或警示等级**；"派了几个子代理"与"某个子代理记了多少活跃时长"都不是等级。
上一版把 `activeMs > 30 分钟` 的大数字染成琥珀（`valueTone: 'warn'`），本轮**撤销**，三条理由：
① 它证明不了"危险"——这张卡连"还在不在跑"都不知道（投影无状态），一个 40 分钟前就跑完的子代理和一个正在流式输出的子代理在这里长得一模一样；
② "干了很久"是正常委派，不是失败，也不是告警；一张对正常长活喊黄的卡会被忽略；
③ "有没有活占着机器"是 `jobs` 的职责（它有真实 `status`），本卡不承担。
因此 `LONGEST_ACTIVE_WARN_MS` 常量与 `valueTone` 字段一并删除——**这个文件里现在没有任何颜色调用**，`valueTone` 在快照里也已消失（见结案报告第五段）。

> 对比过的既有组件清单：`jobs`、`task`、`trajectory`、`counts`、`tool`；另核对了产品自身 UI（输入框模型/推理档、权限选择器、页头、设置页）确认没有更近的展示位置。

## 1. 这张卡回答什么问题

**本会话派出去的子代理是什么：一共几个、几个是可持续的、最近一个带标签的是谁。**
多代理是长跑里时间与成本的主要来源，而它在 rail 上完全不可见——官方 `subagentCatalog` 投影至今没有任何消费者。

它**不回答**"还在不在跑"（投影没有状态字段，那是 `jobs` 的问题），也**不以"活了多久"为主角**（大数字是总数；时长只作为灰字出现，且自带主语）。

## 3. 数据来源

只读 `WidgetStats` 的一个字段：

| 字段 | 口径 |
| --- | --- |
| `stats.subagents` | `SubagentEntry[] \| null`，即官方 `subagentCatalog` 投影（已被 `normalizeSubagents` 归一化）。**目录顺序 = 最旧在前。** |
| `.length` | 派出去的子代理总数 → 大数字 |
| `.mode` | `'one-shot' \| 'continuable'`。「持续型」= 计数后写 `n / 总数` |
| `.activeMs?` | 子代理自己日志里的**活跃轮次时长**：`normalizeSubagents` 从客户端 session list 的 `byId[child].projectionValues.subagentTiming` 取（父会话读不到子会话的 `subagentTiming`，那条键折的是父会话自己的日志）→ **可能整批缺失**，`undefined` ≠ `0` |
| `.createdAt` | epoch ms，投影保证有。用于「最早 … 前创建」与「最近」的判定 |
| `.label?` | 身份标签，可能很长、可能没有 |

契约现状：`SubagentEntry.activeMs` 已进共享契约（`contract/types.ts`）并由 `normalizeSubagents()` 填充，本部件**直接用共享类型**（上一版那个本地 `& { activeMs?: number }` 拓宽已删除）；渲染仍对畸形值防御（`finiteOrNull`），因为卡片永远不能在格子里印 `NaN`。

`null` / `[]` / `—` 的语义：

| 值 | 含义 | 卡面 |
| --- | --- | --- |
| `subagents === null` | 投影缺失（该部署没有 session controller） | **整卡返回 `null`**（见 §0 第 5 问） |
| `subagents === []` | 投影在，但本会话没派过子代理 | **整卡返回 `null`**（同上） |
| 某行没有读数 | 例如没有任何带 label 的条目 | 印 `—` + `tone: 'muted'`，**行不消失** |
| `activeMs === 0` | 子代理存在但还没跑过任何一轮（真实读数） | 灰字印「最久活跃 0s」，不是 `—` |

## 4. 元素为什么这么摆

- **大数字在标题正下方**（`headAfter.big`）：它是总数，是唯一一个不依赖任何可选字段、投影必然能兑现的数字——也是这张卡唯一的主角。不用 `value`——有 `headAfter` 的卡上 `value` 会被推进正文，同一个概念印两遍。
- **灰字自带主语**（`legend`）：`最久活跃 36m12s`，而不是上一版的 `活跃时长 36m12s`。车主的原话是"我知道是最久的子代理的，但很显然其他人不清楚"——灰字必须自己回答"这是谁的、哪个量"。`activeMs` 是父会话绕道取得的量、可能整批缺失，所以它当不了大数字；一个都没有时整句换成 `最早 48m 前创建`（由 `createdAt` 兜底，永远为真），两句都是**关于全部子代理**的陈述，所以留在头部。
- **两行明细贴底**（`bodyAnchor: 'bottom'`）：与 缓存命中 / 工具调用 / 权限档位 同一姿势——头部在顶、明细落在地板上，多出来的高度留在灰字与分隔线之间，而不是吊在明细下面。
- **第 1 行「持续型」= `n / 总数`**：分母是这一行的重点——"2 持续型"离开分母读不出比例（`2` 与 `2 / 4` 是两句话）。
- **第 2 行「最近」的身份放在左列**：这是被**实测逼出来**的一处偏移。`breakdown` 的网格是 `1fr auto`（左标签轨 / 右数值轨），把长 label 放进**数值轨**时数值轨会按内容撑到 245px（内容区只有 124px），左标签轨被压成 `0px`——两行的标签全部消失、第 1 行的数值被顶出卡片（首版的 DOM dump：`gridTemplateColumns: "0px 245.203px"`）。渲染器对长文本的既定处理是**左标签轨的右缘淡出**（`breakdown.tsx`：nowrap + mask），所以身份放左列：再长也只是淡出，`持续型 / 最近` 这组固定词始终可读。工具调用卡的「最慢 <名字>」是同一写法、同一理由。
- **第 2 行的数值是那个子代理的年龄**（`4m 前`）：它讲的是"最新出现的那一个是什么时候出现的"，**不是它活跃了多久**（活跃时长只有灰字那一处）。
- **只有两行，没有第三行**：这张卡能读出的身份读数只有这些。两个候选都被否掉：**「一次性」计数**是第 1 行的补集（总数已经是主角，`2 / 4` 再写一遍分母是同一个 4 出现三次）；**「最早 <label>」**在只有一个子代理带标签时会和第 2 行印同一个名字。与其凑满三行，不如让 16px 的余量留在灰字与分隔线之间（权限档位同样是"两行 + 留白"的姿势）。
- **长 label 不追加 `…`**：可见的截断是渲染器的右缘淡出；部件只把字符串截到 48 字（防病态输入进 DOM），在已经淡出的行里再塞省略号就是第二个截断记号。

## 5. 语气方向（tone 由本部件自己定）

| 元素 | tone | 依据 |
| --- | --- | --- |
| 大数字 / 卡片 | **不染色** | 子代理多不等于坏，它是一个名册计数，没有等级含义 |
| 第 1 行「持续型」 | **不染色** | 持续型不是坏东西，它是一个种类 |
| 第 2 行「最近」 | 缺读数 `muted`，其余默认 | 身份没有好坏 |
| 缺读数 | `muted` + `—` | 没有读数就印 `—`，不伪造 0 |

**为什么撤销原来的 30 分钟阈值**：见 §0 第 6 问。一句话——子代理不需要危险/警示色：绿黄红只表示等级，而这张卡连"还在不在跑"都读不到，更没有"危险"可言。原先的 `LONGEST_ACTIVE_WARN_MS = 30 * 60_000` 与它触发的 `valueTone: 'warn'` 已整体删除；若将来真要重新引入等级色，前提是数据面先给出状态或失败（那时该由 `jobs` 说，而不是这里）。

## 6. 配置项

**无。** 这张卡的读数是"当前名册"，没有需要用户选择的视角，也没有可切换的口径。`simToggle` 只是预览的点击切换（见第 9 节），不是用户配置。

## 7. 空态 / 降级行为

| 情形 | 行为 |
| --- | --- |
| `subagents === null`（投影缺失） | `render` 返回 `null`，不占格子 |
| `subagents.length === 0`（没派过） | `render` 返回 `null`——理由是它会随子代理有无出现/消失，代价已记录在 §0 第 5 问 |
| 一个 `activeMs` 都没有 | 灰字换成「最早 … 前创建」；其余照常 |
| `activeMs` 全是 0 | 灰字印「最久活跃 0s」（真实读数，不是缺读数） |
| 没有任何带 `label` 的条目 | 第 2 行整行变成「最近」+ `—`（`muted`），行不消失 |
| `createdAt` 不是有效数字（防御） | 「最早 …」那句整个不渲染（宁可不印也不编），第 2 行印 `—`；一个数字都不印 `NaN` |
| `createdAt` 在未来（时钟偏移） | `fmtAgo` 夹到 `0s`，不印负数 |
| 卡片自带动作 | **无按钮**，所以没有"必须永远渲染"的义务 |

`render` 是纯函数，唯一读时钟的地方是 `Date.now()`（用于「最早 48m 前创建」与「4m 前」这两个**距离**，距离只有相对"现在"才存在）；时钟在每次 render 里读一次，不缓存、不写回 `stats`。

## 8. 与既有卡的差异

见 §0 第 2 问的六卡对照表。要点：

- 与 **后台作业（jobs）**：`jobs` 有真实 `status`，管"有没有活正在占着机器"；本卡没有状态，管"派出去的是些什么"。`jobs` 的明细可以印"最久 <作业> 12m4s"（正在运行），本卡的时长永远带「活跃」二字（已记账，不代表还在跑）。**卡面不出现「运行中」。**
- 与 **任务（task）**：`todos`（我要做什么）vs `subagentCatalog`（派出去过谁），零字段重叠。
- 与 **工具调用（tool）**：工具卡统计**本会话自己**的调用折叠（`stats.tools`）；子代理的工具调用记在子代理自己的日志里，不计入父会话。两张卡的"最久"是两个层级。
- 与 **轨迹（trajectory）/ 轮次（counts）**：都是父会话自己的节拍，与子代理无关。
