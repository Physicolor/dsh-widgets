## 0. 开工前的强制审计（答不上来不许动手）

每新建或改版一个组件，**动手之前**先逐条回答，并把答案写进该组件 `README.md` 的**第一节**（标题就叫「§0 审计」）。这是本轮新增的**交付物**，缺它即未完成。

1. **这个信息是不是已经在别处更方便地展示了？** —— 把**产品自身 UI**（输入框的模型与推理档、权限选择器、页头、设置页）也算进"别处"，不只是 rail 上的卡片。有一处更方便 → **不做**。
   *（`model-config` 会话配置就是因为输入框已经常显模型+推理档而被删除的。）*
2. **有没有功能高度重合的既有组件？** 列出名字 + 它的口径，逐条说清差异：**窗口 / 范围 / 单位 / 时态**。说不出差异 → 合并或放弃。
3. **如果不合并，用户不读文档怎么分清两张？** 名字、**大数字的单位**、灰字的第一句，必须自己回答"我是哪个"。
   *（反例：`窗口预测` 与 `额度管理` 都印百分比 → 前者已改名 `限流预测`。）*
4. **这个大数字是什么单位、什么范围、什么时间点？** 需要一句解释才能看懂的数字 = 不合格。
   *（反例：目标卡的 `0 / 256` —— DSH 的 `defaultMaxGoalRounds` 就是 256，一个还没有任何轮次的 goal 会印它，对用户毫无意义。）*
5. **它应该一直在，还是可以消失？** 用户**主动装进 rail** 的卡会因缺失数据而"突然出现/消失"，那会打乱布局。缺数据时显示**安静的空态**，不要隐藏自己。（*例外*：新增的、用户还没决定要不要留的卡仍应隐藏 —— 由任务书明确指定用哪种。）
6. **颜色有没有被赋予一个用户能说出的含义？** 绿/黄/红**只表示危险或警示等级**。没有等级含义的量**不许染色**。

在结案报告里**单独一段**交代这六问的答案，并列出你对比过的既有组件。

## 1. 本轮车主的逐条要求（按组件）

### 1.1 `subagent` 子代理 —— 重新定职责
- **灰字必须自己说清是什么**：现在只有一个时长，用户不知道那是"最久的那个子代理"的活跃时长 → 写成 `最久活跃 47m56s`（中英同步）。
- **去掉琥珀色**：子代理不需要危险/警示色。大数字一律正常前景色；`valueTone` 不许出现（也顺带说明为什么原先那个 30 分钟阈值不成立）。
- **与 `jobs` 分化**（见 `BATCH-3-AUDIT.md` §4）：`jobs` 负责"有没有活正在占着机器"（有真实状态），`subagent` 负责"**派出去的是些什么**"（身份：几个、几个可持续、分别是谁）。不要再以"活了多久"为主角。
- 明细仍是 ≤3 行的 `breakdown`，但内容改为**身份类**读数。`subagentCatalog` **不携带状态**，卡面任何位置都不许写"运行中"。

### 1.2 `guard` 权限档位 —— 极简版
- **复用官方权限图标**：渲染器已新增 `headIcon` 字段（`WidgetRenderOut.headIcon = { name, tone? }`，名字取自 `HeadIconName`：`permission-read-only` / `permission-workspace-write` / `permission-full-access`）。图标本身就是官方选择器用的那三个 shield（已按官方 path 复制进 `render/icons.tsx`），**不要自己画**。
- 版式：**图标放右上角**（`headIcon`），**档位名放左下角**，**其余文字全部清空**。
  - "左下角"用 `bodyAnchor: 'bottom'` + `value`（`value` 是正文位置的数字/短文本，贴底后落在左下角）；标题（`card.guard.title`）仍保留在最上。
  - 图标大小由渲染器定（`headIcon` 是 34px 基准），你不需要给尺寸。
  - 档位名：沿用官方的显示名映射（你上一版已经做了 `PRESET_LABEL_KEYS` + `titleCasePreset`，保留）。
- 危险族仍可 `valueTone: 'danger'`（那是**真的等级**：完全访问 = 危险），但**不许** `valuePulse`。
- 若 `permissions` 为 `null`（部署未组合权限服务）→ 仍返回 `null`（这张卡是新增可选项，未装即不显示）。
- 明细（`breakdown`）**删掉**：用户要求"其它文字全部清空"。

### 1.3 `jobs` —— 只改名
- 中文名 `后台作业` → **`后台任务`**（与 DSH 官方一致），英文 `Background Jobs` → **`Background Tasks`**。卡面结构、行为、tone 全部不动。
- 改完确认 `locale.zh/en` 里所有出现"作业/Jobs"的文案同步（标题、描述、行标签、sim 提示）。

### 1.4 `goal-progress` —— 一直在 + 数字要有意义
- **永远渲染**（不再因 `goal === null` 返回 `null`）：没有目标时显示**安静的空态**（标题 + 一行说明，如「当前没有目标」），不要弹进弹出。
- **数字必须有意义**：
  - 大数字改为**阶段词**（`进行中 / 已暂停 / 受阻 / 已完成 / 无目标`）—— 一个不需要解释就看得懂的词，比 `0 / 256` 强。
  - `roundsStarted / maxGoalRounds` 只在**有意义时**才印：`roundsStarted === 0` 时**不印这一对**（还没有任何轮次被准入 ⇒ 没有进度可言，只有上限不是进度），印 `—` muted 或者干脆把它换成别的读数；`roundsStarted > 0` 时才印 `12 / 40` 并**必须**让标签说清是"轮次 / 上限"。
  - 背景（写进 README）：DSH 的 `dsh-goal` 配置项 `defaultMaxGoalRounds` 默认 **256**，所以任何用 `create_goal` 建的目标在还没跑轮次时都会给出 `0 / 256` —— 这是这张卡原来最难懂的那一格。
- 明细行 ≤3，建议：目标（objective 截断）/ 轮次 / 最近变更；`blocked` 时灰字让位给 `blockedReason`（保留上一版这个设计）。
- `example` 要覆盖：**无目标**（空态）、进行中（`12 / 40`）、刚创建（`0 / 256` → 应当不出现这对数）、受阻、已完成。

### 1.5 `sys-disk` 磁盘与自检 —— 重排版式
- **第一行灰字与图表重复** → 删掉重复的那半（图表已经在说每块盘的剩余比例）。
- **第二行让用户看不懂**（`会话日志 346 文件 · 345M · +13/h`）→ 要么改成一句自解释的话（说清"这是 DSH 自己的会话日志占用，+N/h 是最近一小时新增"），要么删掉并把信息并入别处。**必须选一个并在 README 说明**。
- **图表改横向**：`chart.kind: 'bars'` 是**竖直**柱；横向条请用 `kind: 'quotas'`（每行：标签 + 右侧百分比 + **分段条**，正是"横向"的既有原语）—— 或者你论证后选择 `kind: 'bars'` 并把"横竖"的解释写清。**先读 `render/charts/` 里这两个原语的实现再决定，不要凭猜**。
- **语义**：柱子（填充部分）表示**已使用量**，文字表示**剩余量**。注意 `BarDatum.ratio` / `quotas.pct` 在这些原语里都表示**填充比例**，所以传"已用比例"，文字侧印"剩余"。（上一版传的是"剩余比例"，正好相反。）
- 大数字仍是"最紧张那块盘的剩余量"（带盘符），这条保留。

### 1.6 `sys-power` 供电 —— 加图标 + 去掉占位
- **右上角**用 `headRing` + `headIcon` 里的电池：`headRing: { ratio: 电量/100, tone, icon: 'battery', label: '100%' }`（`HeadRingIcon` 已新增 `'battery'`）。环形本身就是电量，图标在环心。
  - `percent === null`（无电池）→ **不给 `headRing`**，也不要 `valueTone`，显示安静的"无电池"形态。
- **下面「剩余」那一行**：插电时（`minutesLeft === null`）**直接不显示这一行**，不要印 `—`（用户明确说：一个不存在的读数不该占位）。用电池且有估时 → 正常印 `2h 14m`。
- 「供电」与「电源方案」两行**与灰字有重复**（灰字已有 `插电 · 平衡`）→ 按"一个读数只印一次"消重：建议灰字只留**来源**（`插电`/`用电池`/`未知`），方案留在明细行；或反过来。**自己定一个并写进 README**。

### 1.7 `sys-procs` —— 只改名
- `内存大户` → 用**专业学名**：建议 `进程内存占用`（Process Memory）。`manifest` 的 name/desc 与 README 同步；卡面结构不动。
- 顺带确认 `card.sys-procs.title` 用的是新名字。

### 1.8 `github-notify` 待我处理 —— 标明来源
- **单看不知道与 GitHub 有关**，而且将来可能有别的平台的"待处理" → 用**品牌图标**：`headIcon: { name: 'github' }`（GitHub 官方 mark 已按 Octicons path 复制进 `render/icons.tsx`）。
- 英文名可考虑 `GitHub · To Review`（或保留短名 + 图标）；中文名建议 `GitHub 待我处理`。**名字里带平台，图标也要有**，两处都做。
- 其余（匿名返回 null、键集恒定、capped 印 `30+`）全部保留。

## 2. 渲染器本轮新增的两个字段（用它们，不要自己造）

| 字段 | 形状 | 用途 |
| --- | --- | --- |
| `headIcon` | `{ name: HeadIconName; tone?: BarDatum['tone'] }` | 头部**右上角的裸图标**（身份标记，没有环）。与 `headRing` 互斥，共用同一个槽位。 |
| `HeadRingIcon` 扩了 `'battery'` | `headRing.icon: 'battery'` | 电量环的环心图标。 |

`HeadIconName` 目前只有 4 个值（三个权限 shield + `github`）。**需要新的图标 → 不要自己加**，在结案里说明需要哪一个，由主 Agent 加进共享层（并给出图标的官方来源）。
