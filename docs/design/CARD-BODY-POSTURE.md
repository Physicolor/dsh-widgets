# 卡片主体姿态标准（CARD-BODY-POSTURE）

> 2026-10-14 制定。触发事故：`task-timer@2x4`（任务计时）第一版把 `headAfter` 大数字放在标题下、
> 四个 figures 紧贴其后，卡片下方留出 **51.6px 空带**（一眼可见的"没做完"）。它通过了 Worker 自检、
> G1–G12 全部闸门、离线画廊几何探针、以及一次独立 Review，最后由车主看图发现。
> 本文件把「主体姿态」从审美问题变成**有判据、有参照卡、有机器断言**的规范项。

## 1 一句话规则

**2×4 卡片的主体（body）只有一行内容时，必须贴底（`bodyAnchor: 'bottom'`）；
多行内容可以贴着头部往下排。** 主体之下不允许留出超过 `36px × scale` 的空带。

## 2 为什么需要它

`headAfter` 的存在会把卡片切成「头部 + 主体」并默认 **top-aligned**（主体紧接头部）。
这对**多行**主体是对的（`task@2x4` 的四行待办：行数自己填满卡片）；
对**一行**主体是灾难——一张 150px 高的卡只用了上半张，下半张全空。

两条互不相容的合法姿态因此并存，选择**取决于主体的行数**，而不是取决于卡片尺寸：

| 姿态 | `bodyAnchor` | 什么时候用 | 已发行参照卡 |
| --- | --- | --- | --- |
| **贴底（floor）** | `'bottom'` | 主体只有**一行**：一行 figures、一行大数字 + 说明、一排环 | `harness-board`（会话概览）、`sys-disk@2x4`、`context-water@2x4`、`heatmap-bars@2x4` |
| **跟随头部（top）** | 缺省（`'top'`） | 主体有**多行**且会填满卡片 | `task@2x4`（四行待办）、`peak-pricing-board@2x4`（时段表）、`github-board@2x4` |

无 `headAfter` 的卡（纯 figures / 单值度量）本来就贴底，不需要显式声明。

## 3 判据（可测量，不接受"看起来还行"）

`scripts/probe-geometry.cjs` 的 **POSTURE** 断言（Phase 1 离线画廊 + Phase 2 实时 rail 都跑）：

- 对每张 2×4 卡，量出「内容最深的**叶子**节点底边」到「卡片内容底线」的距离 = 空带 `gap`；
- 容器不算：被拉伸的 flex 容器底边恒等于卡片底线，量它永远得 0；
- 判定：`gap > 36 × scale` → **FAIL**，并直接给出修法提示（`bodyAnchor:'bottom'` + 本文件）；
- 例外必须逐条登记在探针的 `POSTURE_OK` 里并写明理由（与 `DATA_TRUNCATION_OK` 同一纪律）。

**这道断言被证伪过**：把 `task-timer` 改回顶对齐后实测 `51.6px > 36px` → FAIL（2026-10-14 实测输出），
改回 `bodyAnchor:'bottom'` 后全量 24 张 2×4 卡最大空带 26px（`sys-disk@2x4`）→ PASS。
不能失败的断言不算验收。

## 4 规范三件套的落点（防止再犯）

| 环节 | 必做 |
| --- | --- |
| `03-specification.md` | `visualRequirements` 必填 `bodyPosture: 'floor' \| 'head'` 与 `referenceCard`（一张**已发行**同族卡的 id）。新卡必须与参照卡并排截图对比 |
| `04-worker-instructions.md` | Worker 交付前必须给出「参照卡 id + 为什么同族」；只写"参考某布局"不算 |
| `05-review-checklist.md` | Layer 2 逐条核对：① 主体行数 ↔ 姿态是否匹配；② 空带是否 ≤ 阈值；③ 是否与声明的参照卡同族。**没有参照卡的卡直接 REWORK** |
| `06-acceptance.md` | 验收命令含 `node scripts/probe-geometry.cjs`（POSTURE 断言在内），并对 2×4 交付物附离线画廊图 |

## 5 复盘：这次为什么一路通过

1. **spec 缺姿态字段**：Worker 收到的规格写了「2×4 = headAfter + 一行 figures」，没写主体贴底，
   也没指定参照卡。Worker 严格照做了——错在规格，不在执行。
2. **闸门只看数据与溢出**：G4 比对 render 输出的 JSON（数据完全正确），
   几何探针只问「是否溢出 / 文案是否被截断」。"里面留了 51.6px 空" 这类缺陷对所有自动闸门不可见。
3. **Review 被规格叙事带偏**：复核看到我在 spec/记录里写的"与 harness-board 同族"，
   就按同族接受了顶对齐；而真正的同族参照（`harness-board` 是**贴底**的）没有被逐像素对照。
   → 复核规则因此改为「必须对参照卡同姿态实测，不接受文字声明」。
4. **验收表里没有"版式"这一栏**：我把这张卡的空带写成了"待裁决"而不是缺陷，
   说明当时连我自己都没有把它归入验收项。本文件 + 上述三处规范落点就是补这一栏。

一句话：**没有参照卡、没有可测量判据的视觉要求，等于没有验收。**

## 6 第二类事故（同日）：适配**交给你的宽度**，而不是你以为的宽度

**事故**：`秒表` 第一版的表盘把两个圆盘与读数的尺寸按「150px 卡的 126px 内容列」写死
（`52 + 22 + 52 = 126`，零余量），在 150px 画廊里刚好，到市场/组件配置预览的 **285px** 档
取整后左右各溢出 ~5px，被卡片 `overflow: hidden` 裁掉——车主截图（2026-10-14）。

**真根因（两处，缺一不可）**：
1. `CardBody` 交给 rich 块的是**外框宽度**（`boxW`：整卡宽，或 2×4 的 `2·unit+gap`），
   而卡的内边距画在里面。按外框拟合 = 高估了约 `2 × cardInnerPad` 的可用宽度；
2. 字宽用「平均 0.55em/字符」估算，而产品的 tabular 数字实测 ~0.66em、冒号/点 ~0.32em。

**修法（已落地）**：`render/rich/timer-face.tsx` 里所有尺寸都从 `width − 2·cardInnerPad(unit) − 2·inset`
推导，字宽按**逐字符**的 em 预算（含 4% 安全余量），圆盘按 `available ÷ 2.6` 收缩——
任何 scale 都不可能溢出。

**为什么第一版没被发现（闸门缺口，已补）**：
| 缺口 | 补法 |
| --- | --- |
| 现有 COPY 检查只看**具名文本节点**（title/value/sub/legend…），rich 块内部的读数与图形完全不在检查范围 | `probe-geometry.cjs` 新增 **INNER-FIT**：逐元素量「是否戳出卡片内容框」，例外必须登记 |
| 画廊**只渲染 150px**，预览档（190/285）从没有过离线样张 | `scripts/preview/gallery.mjs` 的 head-fixture 页把 **SIZES 扩到 150/190/285** 并加入三个 timer 变体；探针新增 **PHASE 3** 对整页做 INNER-FIT |
| 我复核时只看 150px 画廊图 | 交付 2×4 / 表盘类卡片必须看 **285px 档**（`docs/preview/cards/_fixture-*@285.png`） |

**证伪**：把宽度预算改回按外框拟合，fixture 立刻 FAIL（`timer-stopwatch@150/190/285` 各溢出 3.6–11.7px）；
修正后 150/190/285 三档全绿。**同样地，只有当检查能失败，它才算验收。**
