# FOLD 2026-10-28 — 折叠时对话区的移动回到合成器

车主报告：「上一轮修复了展开/收起组件区域时组件区和对话区整体的卡顿，但对话区平滑移动的动画消失了」，
「置顶摘要卡片的对话区域动画同样卡」；第二轮补充：「输入框也是对话区域的一部分，也需要平滑动画」。

上一轮（[FOLD-2026-10-27-inset.md](FOLD-2026-10-27-inset.md)）的结论只对了一半：
让位（`[data-conversation-scroll]` 的 `padding-right`）逐帧 tween 会整段重排，确实是卡顿的病因；
但把它改成「一次落地」同时删掉了**眼睛真正在看的那段运动**——点下去文字瞬移，只有组件栏自己滑进来。
这一轮把「一次落地」保留，把运动重建为**阅读栏两个占位者一起平移**：文字窗格是合成器
`translateX`，输入框卡片是相对定位的 `left`（绘制期偏移，不能抢文字列的重排，也不能动组件栏的锚点）。

## 1. 为什么不恢复 tween

tween 的成本不在「插值」而在「每帧一次完整重排 + 同住插件的强制读」。2026-10-27 的收据：
同机同会话，只注入 `[data-conversation-scroll]{transition:none}`，折叠窗口 p95 帧间隔
**56.1ms / 36.1ms → 19.9ms / 19.8ms**，窗口内 style recalc 377ms → 174ms。恢复 tween 等于恢复这份账。

## 2. 修法：一次落地 + 合成器平移（文字 + 输入框）

`src/client/rail/fold-inset.ts` 重写（`armFoldInset()` / `settleFoldInset()` / `releaseFoldInset()` 三出口不变）：

- 折叠开始时仍先武装 `html.dsx-fold-inset`（`transition: none !important`），让新值在**第一次重算**里落地。
- 让位一变就要**在同一帧里**开始平移，否则会闪一下（2026-10-28 第二轮报告的「抖动」）：
  - `index.ts` 在翻 `dsx-stats-active` 之后**同步**调 `syncFoldInset()`（强制一次重算，读到的就是新值），
    折叠自身的那次变化因此落在同一个任务里；
  - 同住插件的写入（置顶摘要约在翻类后 +25~50ms 发布）由窗格上的 `ResizeObserver` 接住——它在 layout
    之后、paint 之前回调，所以那一帧画出来的就是已经带偏移的画面；
  - rAF 轮询保留为兜底。三者共用 `lastPad`，同一次变化只会平移一次。
  曾经的做法是「下一帧再读」，于是每个折叠的第一帧都画在新位置、下一帧再跳回旧位置再滑——文字和输入框
  一起闪，而且两个方向闪的时机不同（开=自己的类，关=同住插件晚一帧），看起来就是「抖」+「展开/收起不一致」。
- 折叠期间每次读到的变化都按 `Δ/2` 同时给**阅读栏的两个占位者**发 WAAPI 动画：`composite: 'add'`、
  `fill: 'none'`、时长与曲线取自 shell 本来会给这条声明用的 `transition-duration` /
  `transition-timing-function`（武装前读，抑制期间它算出来是 `none`）：
  - 文字窗格 `[data-slot="conversation.session"] [class$="_viewArea"]` → `translateX(Δ/2 → 0)`（合成器）；
  - 输入框卡片 `[data-composer-seat] [data-composer-card]` → 相对定位的 `left: Δ/2 → 0`（绘制期偏移）。
- 位移量的来源：两者都在内容盒里居中，`padding-right` 变化 `+Δ` 把它们移动 `−Δ/2`；从新布局出发先加
  `+Δ/2` 就是旧位置，动画到 0 就是新位置——与旧 tween 的视觉路径逐点相同。
- 每帧读到的变化都单独平移（`composite: 'add'` 叠加）：折叠期间第二次写值（置顶摘要约在
  +30~46ms 才发布自己的让位）不会跳，反转也不会跳；`fill: 'none'` 结束后什么都不留。
- 上一轮的 `dsx-fold-inset-hold`（关闭时钉住旧值）**删除**：平移本身就从旧位置出发，
  钉子不再需要，且它会让关闭方向先停住再跳。

### 为什么是「窗格 + 输入框卡片」，而不是滚动容器

dsh-widgets 把抽屉 portal 进编辑器卡片里的 `[data-composer-overlay]`，它**在** `[data-conversation-scroll]` 内部。
给 `position: fixed` 元素的祖先加 `transform` 会把这个祖先变成它的包含块，滚容器一平移，整条组件栏就会
被重新锚定——所以滚动容器不能动，而**输入框卡片本身也不能用 transform**（它就是那条 portal 的祖先）。
卡片是 `position: relative`（shell 自己给了 `left: 0px`），因此改用相对定位的 `left`：相对偏移在绘制期
生效（不重排文字列），并且**不会**成为 fixed 后代的包含块——实测 `left: 135px` 时卡片整体右移 135px，
组件栏 x 恒为 1137.3。代价是这一段走主线程（单元素绘制偏移）而不是合成器；同版本 A/B 中它与纯窗格
平移的差异落在噪声内。

## 3. 置顶摘要（同因）

`dsh-pinned-summary` 的 `--dps-right-space` 也是这条声明的一支，上一轮只让 dsh-widgets 的单向路径变成
一次落地，卡片自己的折叠仍靠 shell 的 padding tween——所以「卡片的对话区动画也卡」。

`src/card.js` 新增 `panSpace()` / `publishSpace()`：一次让位变化 ≥24px 且不是连续流时，
先加 `html.dps-inset-pan`（`transition: none !important`）、写值、再对同一个窗格发同样的平移；
`--dps-right-space` 的相等写仍然交给 `setHtmlVar` 去重（会话重挂会清掉这个变量，不能按值相等直接返回）。
两个插件不重复平移：`html.dsx-fold-inset` 存在时 dsh-widgets 的 watcher 负责，置顶摘要让路；
`html.dsx-live-width`（宽度拖拽，claim 每帧变）与「100ms 内连续写」保持原 tween，不逐帧发平移。

## 4. 实测（live，1707×1067 @DSF1.5）

`scripts/probe-fold-inset.cjs`（已按新机制重写，receipt → `.probe-fold-inset/report.json`）：

| | close | open |
|---|---|---|
| 让位取值 | `570px → 300px`（2 个值） | `300px → 570px`（2 个值） |
| 折叠期间 padding transition | 0 帧 | 0 帧 |
| 窗格平移 | 29 帧，`-121.0 → -135.0`（半量）→ 0 | 17 帧，`127.6`（半量 135）→ 0 |
| 输入框卡片位移 | `135px`（x `315 → 450`），与窗格同步 | `-135px`（x `450 → 315`） |
| 组件栏自身 x | 恒定 `1137`（未被平移带走） | 恒定 `1137` |
| 折叠窗口 p95 | **12.5ms**（>50ms 帧 2） | **20.8ms**（>50ms 帧 1） |
| 残留 | 无 `dsx-fold-inset` / `dps-inset-pan` / `transform` | 同左 |

同版本 A/B（`Element.prototype.animate` 只对窗格打桩 = 上一轮的「一次落地」）：

| | pan open | no-pan open | pan close | no-pan close |
|---|---|---|---|---|
| p95（两轮） | 14.7 / 29.2ms | 29.1 / 25.1ms | 12.6 / 29.3ms | 16.6 / 12.4ms |

即窗格的合成器平移在本机上**没有可测成本**（差异在噪声范围内）。输入框卡片的 `left` 走主线程绘制偏移，
A/B（只给卡片的 `animate` 打桩）在本机高负载窗口里是 close 41.5/28.2 vs 28.1/28.1、open 138.9/48.4 vs
55.5/41.7——首轮差异主要是页面预热，稳定状态下增加不超过个位数毫秒；这不改变取舍：唯一的替代是
「输入框不动」。

置顶摘要自己的折叠（卡片仓库的 `scripts/probe-inset-pan.cjs`，同一机制、同一窗格选择器）：
`0px ↔ 300px` 一次落地，窗格 `±150px`、输入框卡片 `∓150px`（x `536 ↔ 386`），两个方向都通过；
组件栏与卡片同时存在时关闭（`570 → 300`）只出现**一次**平移（首帧 -107 vs 半量 -135，另一支让路后
由本插件的 watcher 接管），没有双倍位移。

「没有闪帧」现在由 `probe-fold-inset.cjs` 断言：**第一个带新让位取值的采样帧必须已经带着平移**
（修复前那一帧是 `tx=0`，下一帧才跳回去）。逐帧追踪（`.tmp-jitter.cjs` 一类的一次性脚本）在修复前
close 采到 `t107 pad300 tx0`、修复后同一帧是 `pad300 tx-135`。

主线程成本（CDP `Performance.getMetrics`，一次折叠窗口）：加输入框平移前后布局次数都是 27–28 次、
`LayoutDuration` 0.075–0.104s、`RecalcStyleDuration` 0.19–0.25s——`left` 是绘制期偏移，不额外触发布局。
这一页折叠本身仍有 0.5–0.7s 的主线程任务（组件栏挂载 + 同住插件），所以帧率类断言在高负载机器上会抖，
探针把帧预算只报告不断言。

## 6. 记录而不是断言的两件事

- 关闭方向首帧的平移量随「谁先写值」浮动：置顶摘要存在时它约在 +30~46ms 才发布，采到的首帧是
  半量的 80%~100%（曲线已经走了一点），因此探针断言的是「≥60% 半量且不超过半量」，不是等值。
- 输入框卡片用的是相对定位的 `left`，不是 `transform`：它是组件栏 fixed 抽屉的祖先，`transform`
  会把抽屉重新锚定；相对偏移只影响绘制，不重排文字列。代价是这一段在主线程（一次单元素绘制偏移），
  不是合成器；`[data-composer-card]` 的 `left` 若不是长度（`auto`）则自动跳过输入框平移。
