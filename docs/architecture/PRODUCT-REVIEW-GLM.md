## 0. 结论先说

### 0.1 三句话总评

1. **设置页的问题不是"没设计"，是"过度解释 + 盲调"。** 这个页面有分组、有控件纪律、有官方骨架——底子比绝大多数插件好。它显得不清爽，是因为几乎每行都拖一句灰色说明（一半在复读标题），层级只有"粗体/非粗体"一档，而最关键的：**设置窗是模态的，把被设置的那条 rail 完全遮住了**——用户在盲调外观与动画。
2. **市场页有一个真缺陷**：搜索只匹配"组的代表组件"的名字，搜「时钟 / GPU」很可能空手而归（`MarketTab.tsx:179-180`）。
3. **社区瓶颈不在物料，在分发与回流**——README 首屏、官网、海报/演示生成管线全都超配了；缺的是把看的人带回来的通道（应用内链接、GitHub Releases）和把作品送出去的动作（渠道投放）。且 npm 下载数**不能当用户数**（作者确认：DSH 插件下载大量来自自动化 agent、市场镜像与站点拉取）——真实人类信号需要自建测量面。

## 2. 设置面板评审（「组件设置」tab + 三 tab 整体）

### 2.1 信息架构现状（精确盘点）

三 tab 顺序：**组件配置 → 组件市场 → 组件设置**（`Settings.tsx:36-40`）。页面用官方骨架（`h2` 标题 18/26 + 一句 intro 13/20，`panel.module.css:247-261`），tab 条是底部 2px 下划线式（`.dsx-tab`，8px 2px padding，13px 字）。

值得先肯定的三点：**控件纪律**（数值=Stepper、离散=Select、布尔=Switch，`Settings.tsx:53-70` 注释成文）；**列/行/组件数相邻**（第三个是前两个的乘积，`maxWidgets` 被钳制时降级显示 + hover 说明，`:177-187`）；**组头有标题有描述**（`.dsx-set-group-head`，后组 22px 顶距分章，`primitives.module.css:365-379`）。2026-10-01 的自查（`:61-70` 注释）已经修过一次"按加入顺序排的扁平列表"——那次修的是**分组**，本轮要说的是剩下的**视觉与认知**问题。

### 2.2 摆放逻辑评估

**Tab 顺序**（配置→市场→设置）是对的：主任务（管理已装）在前。问题不在顺序，在**命名**：

- 「组件配置」与「组件设置」只差一个字，且两者在日常语感里是同义词。视觉模型独立指出这一点（"poor information scent — tab 名几乎相同"）。英文 Config/Market/Settings 稍好，但中文是主要受众。
- 建议：**已装组件 / 组件市场 / 外观与动画**（en: Installed / Market / Look & Motion）。改名成本 = 3 个 i18n 键 + G4 基线重生。

**组顺序**（网格与尺寸最先）可商榷：新用户最先想动的是"长什么样"（外观、放大），最后才关心网格数学。但改组序收益小于改名，列为可选。

**两个孤悬组**：「组件设置面板」组只有一行还是死的（代码评审 S-2 已判死刑，从产品侧再补一刀：一行组在视觉上就是断头路）；「对话区」组一行，且它配置的其实是**宿主的**输入区状态条，不是组件——组名改成「与宿主界面」更诚实，或与未来其它宿主类开关合并。

### 2.3 逐项评审（17 行）

| 行 | 判定 | 说明与修法 |
|---|---|---|
| 最多列数 | **保留** | 名称/单位/说明都对 |
| 可显示的最多行数 | **改名** | 「可显示的」前缀与「最多列数」句式不一致 → **最多行数** |
| 最多组件数 | **移除（首选）** | 最难懂的控制：上限=列×行，还需 Tip 解释"被覆盖"。而**没有任何场景需要"比座位更少的上限"**——想少显示就少装。作者自己都让默认值满足 2×5=10（`prefs.ts:189-191` 注释）。移除后 `effectiveMaxWidgets` 恒等于列×行，Tip、capped 分支、一个 prefs 字段全删。保守方案：降级进「高级」折叠区 |
| 卡片基准边长 | 保留，desc 可减负 | 三层机制（最小/10px 档放大/5 行上限）是真复杂，但一句话够："卡片最小边长；空间够时自动放大"。机制细节挪 ？hover |
| 组件间距 | **保留** | desc「同时作为组件区四周留白」有信息量，保留 |
| 只显示完整组件 | **保留** | 好例子：不解释会误解（截半的卡去哪了），desc 该留 |
| 连续曲率圆角 | 保留，降术语 | 「超椭圆（squircle）」对多数用户是天书 → desc 改"更接近 iOS 图标的圆角过渡" |
| 圆角档位 | **保留** | 唯一 Select，12% ≈ 旧 16px 的锚点写得好 |
| 无极变化（连续跟随） | **改名** | 标题最费解的一行 → **连续跟随放大**；desc 其实讲的是"开=逐帧跟随，关=吸附点间补间"，保留但缩短 |
| 悬浮放大倍数 | 保留，**删 desc** | desc「被悬浮组件的峰值放大倍数」= 复读标题 |
| 展开方式 | **重构**（见 PR-04） | zh desc 约 180 字，是全页最长段落——说明这一组不该以现在形态暴露 |
| 打开起始缩放 / 位移曲线 / 回弹幅度 / 缩放曲线 | **收进折叠** | 四行 + 两个可拖画布是专家界面；CurveRow 的 1.8s 回放点是亮点，收进去也不浪费 |

### 2.4 视觉诊断：为什么"感觉不美观"

这是你问的核心。综合 CSS 数值与两张截图的视觉模型诊断，**四个根因，按贡献排序**：

**① 解释噪声（最大头）。** 每行 = 14px 标题 + 12px 灰 desc + 控件（`Settings.tsx:90-98`），17 行里约 8 行的 desc 在复读或半复读标题。整页近一半的"墨水"是 12px 三级灰小字——这就是"不清爽"的主体。对照 macOS 系统设置 / Raycast：自解释选项只有光标题一行。**修法**：desc 只保留 4-5 行真正需要解释的（卡片基准边长、只显示完整组件、连续跟随放大、圆角档位、隐藏状态条），其余全删。这一条改完，页面观感立变，且零结构改动。

**② 层级只有一档。** 组头标题与行标题同为 14px/22、同色，只差一个 600 字重（`primitives.module.css:383-388` vs `Settings.tsx:93`）；组头自己还带一行灰 desc。结果是"灰字块与灰字块"的均匀肌理，眼睛没有锚点。**修法**：组头只留标题（删组 desc——六条组 desc 全是可推断的）、字重 600 → 600 + 字距或 13px/600 + 上色徽标；行与行之间维持 hairline，但**去掉每组最后一行的底线**、组间已有 22px，可再拉到 28px，形成"章-节"节奏。

**③ 盲调（结构性）。** 视觉模型确认设置窗是**居中模态、背景压暗**——被设置的那条 rail 完全不可见。改「圆角档位」要 开→看→再开 三步；调「位移曲线」时只能看 CurveRow 自己的回放点，看不到整栏级联的真实效果。这解释了为什么动画组需要 180 字的 desc：文字在补偿"看不见"。**修法分三档**（见 2.5），最小档是在「卡片外观」「悬浮放大」「动画」三组头部放一条**迷你 rail 示意条**（3-4 张缩略卡，随设置即时变化，卡片渲染器 `CardBody` + `exampleOut` 全部现成——市场页 grid 视图就是这么画预览的，`MarketTab.tsx:286-313`）。

**④ 控件体量跳变。** Stepper/Switch 是 30px 级小控件，CurveEditor 是 200px 级画布，同一列表里视觉重量跳变；视觉模型另指出市场页搜索框与视图切换按钮高度不一致（`.dsx-search` 26px 输入 vs `.dsx-viewbtn` 34px 宽——高度差以实测为准，【待验证】）。**修法**：CurveRow 收进折叠区后此问题自动消解；顺手对齐搜索/切换控件高度。

一个反向确认：**不要**给设置页加图标化大卡片（macOS System Settings 那种）——页面只有 17 行，左侧图标导航会把密度打松、还要多一跳。这页的正确方向是"更克制"，不是"更华丽"。

### 2.5 改造方案（三档，可独立实施）

**低档（1-2 天，不动架构）**：PR-02 desc 降噪（纯 i18n 删改）+ PR-03 tab 改名 + PR-06 删死行/改组名 + ② 的组头与底线微调（纯 CSS，G5 基线重生）+ PR-09 恢复默认。做完这档，"不美观"的主观感受预计消掉大半。

**中档（1-2 周）**：PR-04 动画组预设化（顶部一行「动画风格」：标准/柔和/活泼/无动画，映射到现有 CURVE_PRESETS + animScale/bounce 组合；原 5 行收进「自定义…」，默认收起）+ PR-05 移除最多组件数 + ③ 的迷你预览条。

**高档（远期）**：非模态/侧滑设置面板（让 rail 在旁常驻可见）——动大，先靠中档的预览条顶住；或每外观组内嵌即时的"before/after"微型演示。

## 3. 组件市场评审

现状结构：搜索框 + 列表/组件视图切换 → **按组去重的组卡列表**（左色环 + 组名 + 实例数徽章 + 代表组件 desc）→ 点击进预览（Material 共享轴推拉）→ 逐实例（组件×尺寸）添加。设计决定质量很高（FLIP ghost 封存有注释、组卡不加「已添加」的理由成文 `MarketTab.tsx:326-330`）。

**PR-11（P0，功能缺陷）——搜索只匹配组代表**：

```ts
// MarketTab.tsx:179-180（现状）
const marketCards = WIDGETS.filter((w) => { const g = groupOf(w); if (seen.has(g)) return false; seen.add(g); return true })  // 每组只留第一个
const list = marketCards.filter((w) => `${widgetName(w)} ${widgetDesc(w)} ${w.id}`...indexOf(q)...)                    // 只对代表过滤
```

搜索「时钟」「GPU」「GitHub」若不是所在组的**第一个**组件，则一无所获；组标签本身（`group.system`=「系统」）也永远搜不到。修法：过滤谓词改为「`groupLabel(w)` + 该组**全部**成员的 name/desc/id 任一命中」；更进一步，搜索态下直接展示成员级条目（命中哪个组件就列哪个），比组卡更贴意图。**验收**：搜 clock / 时钟 / 系统 / GPU 均命中正确组；空搜索仍回组卡列表。

**PR-12（P2，转化）**：首屏组卡没有任何真实卡片预览与进入暗示（视觉模型："a marketplace where the core action—adding a widget—is invisible"）。而渲染能力全部现成：grid 视图已在画 `exampleOut` 真卡（`:286-313`），list 视图可给每张组卡右侧放 2-3 张 ~44px 缩略卡 + 右缘 chevron。61 张卡是这个插件最强的卖点，市场首页却一张都不露。

**PR-13/PR-14/PR-15**：计数徽章裸数字像通知徽章（`instanceCount` = 组件×尺寸组合数，`:324`）→ 改「N 张卡」或移入预览页；组序照注册表序 → 会话/时间组（新用户最可能先装的）置顶；「已添加」不加在组卡是对的（歧义理由成文），可在**预览页**给「该组已装 2/5」补足信息。

## 5. 首次运行与发现性

默认状态盘点（`prefs.ts:162-192`）：**rail 默认收起**（`railOpen: false`）、默认 2 列、默认装 7 张卡——`cache / counts / tps / llm / tool / tokens / ttft`，全部是 12 行量级的**小文本会话卡**。

**PR-18 的三个子问题**：

1. **首屏说服力**：新用户点开胶囊看到 7 张小文本卡——功能上没错（零依赖、秒可用），但 README 海报/官网卖的是 bento 网格的视觉冲击，期望与实物有落差。建议默认组里**换入 1 张视觉卡**：`clock`（零数据依赖、表盘形态即招牌）或 `sys-cpu`（宿主 sysinfo 开箱即用、双环图）。保留 6 张会话卡不动（信息价值真实）。
2. **发现链**：胶囊（28px 图标按钮）→ rail → 底部「设置」瓦片 → 官方设置窗「组件」节。链条成立但每一环都靠探索。首次展开时（`everOpenRef` 首次为真）在 rail 顶部给一行一次性提示「从 ⚙ 添加更多组件」即可，不需要完整 onboarding。
3. **railOpen=false 本身合理**（尊重用户空间，别改成默认打开），靠 1+2 补足。

**PR-19（待验证）**：装 `github-*` 卡但宿主无凭据时，卡面显示什么？错误码体系里有 `unconfigured`，但用户从卡面能否知道**去哪配**（DSH 的凭据系统）？若卡面只写「未配置」，补一句「在 DSH 设置 → 凭据中配置」就能把死路变通途。落地前先实机确认现状文案。

## 6. 卡片一致性（来自 rail 实机截图的诊断）

`desktop-rail.png`（4 列 + 悬停波峰态）的视觉模型诊断给了一个高份量结论：**rail 与宿主的融合度很好（"looks native, first-class"，8/10）**，bento 观感成立。需要收口的是横向一致性：

## 7. 社区增长策略

### 7.1 现状与核心诊断

**硬数据**（2026-10-22 取自 GitHub API / npm API）：5 stars / 0 forks / 0 issues / 0 watchers / 0 discussions；最后 push 2026-10-14；16 个 topics（质量不错）。npm 周 375 / 月 2,839——按作者校准，**这个数字被自动化 agent 安装、市场镜像与站点拉取污染，只能当分发量级参考，不能当用户数**。真实人类规模目前**不可知**——这本身就是问题（见 7.2）。

**资产盘点（你已经做对的）**：README 首屏完整（海报封面、npm/star/license/兼容性徽章、30 秒安装、自然语言安装替代、诚实且得体的 star 呼吁段 `README.md:64`）；双语 README；官网（交互式 rail、Widget Anatomy、Visual Audit、JSON-LD、88 项自检）；**海报与演示的完整生成管线**（`docs/poster/render.cjs` 生成封面、`scripts/demo/desktop-shots.cjs` 实机截图、`scripts/demo/rail-demo.cjs` 用 CDP 虚拟时间逐帧拍出完美循环 GIF——13fps/88 色/480×784 的 `rail-demo.gif` 就是这么来的，全程无录屏）；dsh-market 截图 PR 的操作文档（`docs/screenshots/README.md` 尾部连 jsonc 示例都写好了）；CI/Pages/OIDC 发布三条 workflow。

**为什么"改 README 效果一般"**：因为 README 从来不是瓶颈。物料已超配，而**看的人不存在**——0 issue / 0 fork 说明访客趋近于零。增长公式是 `曝光 × 转化`，你一直在优化转化侧（README/官网），曝光侧（分发、回流、发布事件）接近空白。下面的行动全部围绕曝光侧。

### 7.2 真实人类信号怎么测（回应"下载数不可信"）

1. **GitHub Insights → Traffic**：unique visitors / referring sites / popular content——这是免费现成的真人计数器。发一次帖、发一次版，看这条曲线的阶跃。
2. **应用内回流链接即测量仪**（G-01）：装了插件的人点进 GitHub 的那次点击，会在 Traffic 的来源里留下痕迹（Web GUI 内点开会带 origin/referrer；桌面端可能无 referrer，可用两个不同的目标 URL 区分：应用内链 `/stargazers` 或 `#from-app` 锚点 vs README 直链）。
3. **Issue/讨论是唯一确证人类的通道**：所以 G-04 的 issue 模板与 discussions 开启不只是礼仪，是仪表盘。
4. npm 下载只用来观察**趋势突变**（某天 ×10 = 某处被推荐了），不用来数人。

### 7.3 行动清单（按 ROI 排序）

### 7.4 视频傻瓜路径（回应"想做但不知道怎么入手"）

你被"剪辑"两个字吓住了，其实这个产品的视频根本不需要剪辑——**产品自己动起来就是全部内容**。三档任选：

- **A 档 · 零剪辑（推荐先做）**：G-03 的 capture 脚本产物就是成品。GIF 进 README/官网/知乎，MP4 直接可发 B 站/小红书。全程不打开任何剪辑软件。
- **B 档 · 录屏 + 两条命令（1 小时）**：OBS 60fps 录 20-30 秒 → `ffmpeg` 裁剪/缩放/打字幕。命令照抄（仓库本来就在用 ffmpeg）：
  ```sh
  ffmpeg -i raw.mp4 -ss 1 -to 22 -vf "scale=720:-2" clip.mp4          # 裁 21 秒、720p
  ffmpeg -i clip.mp4 -vf " subtitles=sub.srt,split[a][b];[a]palettegen[p];[b][p]paletteuse" demo.gif  # 出 GIF
  ```
- **C 档 · B 站 60 秒成品（一个下午）**：分镜脚本照抄——2s 痛点（"对话时 token/余额/温度全靠切页面看？"）→ 20s 演示（开 rail 级联 + 波峰放大 + 市场装卡，用 A 档素材拼）→ 10s 设置页速览 → 5s 两行安装命令 → 3s GitHub 地址。CapCut 导入 + 自动字幕 + 库存 BGM，**无需露脸、无需配音**。同一素材竖版裁切发小红书（#桌面美化 #bento #效率工具 的受众意外契合），横版发 B 站/知乎/X。
