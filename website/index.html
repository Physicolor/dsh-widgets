空间分组Spatial grouping

卡片只有三层：标题行、可选说明、内容块；层与层之间固定 6px 节奏，说明行紧贴标题而不会挤走标题。

整列右缘锚定：卡片放大只向左生长，行距靠累加行高维持，右边缘永远齐平——所以放大时不会把栏推走。

DSH Visual Audit

        
几何告诉我们哪里没对齐，设计规则告诉我们那是否要紧。下面是全部 33 个组件按规则算出的结果——没有神经网络，只有测量与规则。


        

          

            
Layer 1 · 几何测量

            
在浏览器里对真实渲染的卡片取 getBoundingClientRect：内边距、右槽对齐、块间距、溢出、动作区偏移。

          

          

            
Layer 2 · 设计规则

            
声明式规则：主读数是否唯一、字号是否形成层级、动作是否抢戏、分组与密度是否越界、放大后层级是否还稳。

          

          

            
评分公式

            
scoredim = round(100 · Σ wrule / n)
w = pass 1.0 · warn 0.6 · fail 0 · n/a 不计

            
分数只是规则结果的加权和：它不说“漂亮”，只说“符合或偏离这套语法”。

          

        


        

          

          

        

        

        
规则来源：DASH_GRAMMAR.RULES（js/grammar.js），常量对齐 src/client/components.tsx 与 src/client/index.ts。测量在本页真实渲染的卡片上进行；放大稳定性用 unit×1.2 的独立样本复测。

填写需求

          
描述你想要的组件，生成一份可以直接交给 AI Agent 的组件规格。


          

            

              
              
              

                
                
              

              
              
              
              

                
                
              

              
              
              

                
                
              

              
先填好必填项，然后生成规格——它可以交给任何 AI 编码 Agent。

            


            

              

                
Widget Specification

                可直接交给 AI 编码 Agent 的组件规格
              

              
填写表单并点击「生成 Widget Specification」。
生成的规格可以直接粘贴给 AI 编码 Agent，或作为 GitHub Issue 提交。

              

                
                在 GitHub 提交组件需求
              

              
GitHub Issue 接收组件需求；每条需求进入标准生产流程。自动处理在 Roadmap 上，还不是当前能力。
